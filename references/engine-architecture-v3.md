# v3.1.0 计算核心重构说明

## 1. 设计边界

`qto_core.py` 是确定性数值与运行时基础层，不代替合同计量规则，也不把几何推断伪装成合同结论。领域脚本负责识别图纸/BOQ结构、套用经批准的规则、生成专业检查项；核心层负责严格数值、单位换算、状态语义、文件指纹和安全写出。

## 2. 数值契约

- 关键算术优先使用 `Decimal`，不依赖二进制浮点数的显示精度。
- `NaN`、`Infinity`、布尔值、空值和含糊的千分位/小数分隔符不能被默认为合法数量。
- 逗号小数必须显式指定 `decimal_comma=True`；不自动猜测 `1,234` 是一千二百三十四还是 1.234。
- 单位换算必须先确认同量纲；未知单位和跨量纲换算均明确失败，不做隐式转换。
- 换算系数应来自项目批准规则或有来源的人工声明。软件只执行，不替专业人员证明系数的工程适用性。
- 容差必须明确给出，并应与合同、规范或项目质量计划一致；默认容差不是合同规则。

## 3. 状态契约

统一状态枚举：`PASS`、`FAIL`、`WARN`、`NOT_RUN`、`ERROR`。输入缺失、配置不合法、依赖缺失或门禁未执行不得映射为 `PASS`。CLI 退出码约定：`0` 通过，`1` 有发现项，`2` 未运行/执行错误。WARN 是否阻断交付由项目批准的质量策略决定，而不是由脚本私自决定。

## 4. 可追溯性与文件写入

- `sha256_file` / `fingerprint_inputs` 为输入文件生成内容指纹，适用于记录报告的输入基线。
- `atomic_write_text/json/csv` 通过同目录临时文件和原子替换降低中途失败造成的半成品风险。
- `safe_relative_path` 用于将项目相对路径限制在项目根目录内，防止意外读写到根目录之外。
- JSON 输出拒绝非标准 NaN/Infinity；Decimal 以十进制字符串输出，避免报告序列化时丢失精度。

## 5. 版本范围与限制

v3.1.0 新增共享数值核心与回归/入口烟雾测试，并把严格有限数值检查接入关键的口径解析、工程量闭环和 BOQ 算式识别路径。现有各专业门禁仍保留其专用规则和 CLI，以维持兼容；它们不是在本次版本中被逐行推倒重写。后续迁移必须逐个门禁完成：黄金样本、负向样本、边界样本、旧版差异报告、双跑比对、专业负责人批准后，才能替换原实现。

## 6. 生产发布门槛

1. 项目清单、合同计量规则、图纸基准和数量基准已批准。
2. 所有必需门禁为 PASS；WARN 有明确责任人、理由、证据和处置期限；NOT_RUN/ERROR 不得放行。
3. 运行 `python scripts/test_all.py` 并保存完整日志、软件包哈希和环境报告。
4. 至少使用一个经专业负责人确认的真实项目样本完成端到端对照，覆盖不同单位、零量、负值/扣减、舍入、图纸修订、公式引用、缺页、重复项、父子项重叠和单位换算。
5. 任何自动化输出均为辅助证据；合同计量、投标定价、现场申报与支付认证仍由授权人员按合同和适用规范签发。
