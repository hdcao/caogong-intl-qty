# 表外缺席：门禁查不到的另一半（v4.6.3）

> **开工前 + 交付前必读。**
> 来源：`ccj-qty v3.3.0` 的 G17 / G18 / 图册覆盖率闸门 / 敞口四态。
> 该技能 v3.0.0 曾吸收本技能 v4.0.1 的八项口径层机制，之后独立发展；
> 本文只吸收它**分化后独有**、且本技能 v4.6.2 确实没有的增量。

---

## 0. 为什么这是「缺口 1」的另一半

v4.6.2 的整改把反复出错归因为三个机制缺口，其中缺口 1 是
「40+ 门禁全在验内部自洽」。上一轮补的 **G-SRC**（数据源语义体检）抓的是
**「读了错的东西」**——把 `DISCHARGES(m3/S)` 流量列当尺寸列、把 `B=3.00` 示例值当定值。

但内部自洽还有另一半盲区，v4.6.2 没覆盖：

> **漏掉的东西不在表内，所以表内自洽永远查不到。**

| 类型 | 表现 | 表里能不能看出来 | 谁抓 |
|---|---|---|---|
| 读错语义 | 流量当尺寸，算出 5356 而非 9191 | 能（有错数） | **G-SRC**（已有） |
| **表外缺席** | 整册图纸空白、垫石整项漏、墩帽被外包矩形吞掉 | **不能（每个数都对）** | **G-OFF**（本版新增） |

ccj 的两个实测最有说服力：

- **37 张里 16 张是空白页** → 那一册覆盖的量不是算错，是**根本没有算**，18 道门禁全绿；
- **墩柱含量 450 kg/m³ 而常规 120~150** → 分母漏了墩帽，但 `class` 在表里，
  G17 也看不见，只有比率会喊。

**表外缺席不产生错数，只产生「少了一整块」。** 这比读错语义更安静。

## 1. G-OFF 四类判据

```bash
python scripts/gate_off_table.py init   --out takeoff/off_table.json
python scripts/gate_off_table.py check  --file takeoff/off_table.json --strict \
        --out out/g_off.json
python scripts/gate_off_table.py selftest                    # 自带夹具 42 例
python scripts/gate_off_table.py status --code IFA         # 证据强度上限
```

| 码 | 判据 | 级别 | 不合格时 |
|---|---|---|---|
| `COV-0` | 范围内无图纸 | `exit 2` | **未运行**，不是通过 |
| `COV-1` | 每册登记 `pages_total` + (`pages_valid` 或 `blank_pages`) | WARN／strict FAIL | 记「**未核**」，**绝不记通过** |
| `COV-2` | 页数自洽（`valid+blank ≤ total`、非负整数）且 `valid == total` | **FAIL** | 指名图号与缺几张；须先定性该册覆盖的分部是否在范围内 |
| `PAIR-3` | 未声明 `systems` / `structure_system` | `exit 2` | 必搭配件判据**未运行**，不是通过 |
| `PAIR-4` | `component_classes` 里有值既不在 §7 受控词表也不在别名表 | `exit 2` | 拒跑并列出未识别项（防"按文档命名反而关掉门禁"） |
| `PAIR-6R` | `required` 构件整项未建 | **FAIL** | 按 `systems` 的**应有全集**对照，抓"整组未建" |
| `PAIR-6C` | `conditional` 构件缺失 | INFO | 条件应有，按项目/图注判定，不阻断 |
| `PAIR-6E` | `either` 互斥组（如 `pile_cap`/`spread_footing`）全缺 | **FAIL** | 二选一，有任一即满足 |
| `RATIO-0` | 项目未声明 `ratio_bands` | **INFO 未校验** | 明写跳过，**不静默通过** |
| `RATIO-1` | 实测比率落在声明带外 | WARN | 文案固定「**分母疑漏｜也可能是分子重复计**」，由人下结论 |
| `RATIO-3` | band 缺可回查 `declared_by` | **FAIL** | 须含图号/册号/条款/页码（语言无关判据）；**AI 不得自拟带** |
| `RATIO-5` | band 与 observed 键不匹配 | WARN | 未匹配即未校验，不得静默 |
| `OI-1` | 敞口状态只用四态码 | **FAIL** | 写「挂账」= 没写 |
| `OI-2` | `CLOSED` 须有可回查 `basis` | **FAIL** | 「已结」与「没查」同形 |
| `OI-3` | 僵尸标记反查 | **FAIL** | 敞口已 CLOSED，但「推定区/不得进报价/暂列」开关还开着 |
| `OI-6` | `SCOPED` 须有 `pending_count` 或 `basis` | **FAIL** | 空白 SCOPED 不允许 |
| `OI-8` | 混态必须拆条 | **FAIL** | 「已结；但…仍待核」→ 未结那半被状态吞掉 |
| `LEDGER-3` | 台账证据强度超出图册 `status_code` 封顶 | **FAIL** | `--ledger` 交叉比对，超限即拦 |

> **`systems` 与 `structure_system` 是必填契约**（v4.6.4）：
> - `systems`：`bridge` / `culvert` / `road` / `lighting` / `building` / `mep`（可多选）。
>   每个 system 对应一份**应有项全集**，按 `required` / `conditional` / `either` 三档判定。
> - `structure_system`：`simply_supported` / `continuous_on_bearings` / `rigid_frame`。
>   `rigid_frame` 时支座类判据不适用（刚构无支座、无伸缩缝），不会误报。
> - **"应有"永远是有条件的**：把绝对全集当无条件应有，会产生大面积"设计确实不设"的误报，
>   而误报会导致整道门禁被跳过（本项目自己记录过 `R-DW-1` 实测误报 5 处后被跳过）。

**精确匹配，不做前缀模糊**：`bearing` 与 `bearing_pedestal` 若用前缀匹配会互相冒充，
判据当场失效。这是 ccj 在真实数据上踩过的坑。**但代价是必须配别名表**——否则
`elastomeric_bearing`（IFC 标准名）会被判"无支座"。故 v4.6.4 起：精确匹配 + 别名归并 +
未识别即拒跑（`PAIR-4`），三者缺一不可。

**两处口径修正（v4.6.4，此前表述不实）**：
- ~~「页数/空白页机器扫」~~ → 实为**人工逐册登记 + 机器校验自洽性/缺页**。
  `gate_off_table.py` 的 `check` 没有任何 `--pdf`/`--dir` 入口，物理上不读图册；
  全库唯一读页数的地方 `extract_dwg_vector.py:55` 只 print 不落盘。
  故「人工声明目录已列全不算数」这句不成立——**人工登记仍是唯一来源**，机器只防"填得不自洽"。
- ~~「简支按梁片数 × 2 端」~~ → 删。支座数量须**直读支座表/布置图**，
  不得按梁片数推算（该推算已被 `appurtenance-pairing.md` §2.5 案例 5 推翻）。

### 三条红线（不要「优化」掉）

1. **不内置任何基准带 / 惯例值。** 带是项目事实不是常识。把惯例值变成判据，
   正是本技能历史上 ×1.05 系数误判、以及「填方误用挖方表沙丘 6:1（−152,100 m³）」的来路。
   无带就出 INFO「未校验」。
2. **「未核」≠「通过」。** 未登记页数记 WARN（`--strict` 下 FAIL），零数据行同样算未运行。
   与 G-RUN 的「没记录 = 没跑，不许默认通过」是同一条纪律。
3. **比率只指路，不定性。** 带外只报两种可能，脚本不替人裁决；反之带内也不证明完整。

## 2. 敞口四态：「挂账」是形容词，不是状态

ccj 实测：某项目 29 条敞口全标「挂账」，逐条回图核了一遍，**21 条当场能结**。
真正的成本不在闭不掉的那 8 条，在这 21 条被一个词一起埋掉了。

| 状态码 | 含义 | 结案判据 | 能否进合计 |
|---|---|---|---|
| **CLOSED** | 已结·图证；或**已证不存在** | 图号+部位、图面原文/读数、数量已重算 | 可以 |
| **SCOPED** | 口径闭环·数量待计 | 口径有图证 + 已列待数清单 | **不可以**，须隔离 |
| **RFI** | 图面确实没画 | 指出缺哪一类 + 说明为什么这张图画不出它 + 已发函 | 按「估算」+ RFI 号 |
| **EXTERNAL** | 图外条件 | 依赖哪个外部输入 + **量化敏感度** | 标「估算」+ 敏感度 |

> **最硬的一条**：凡归 `RFI` / `EXTERNAL`，必须回答
> **「下一轮读图能不能解决」**。答「能」的不是 RFI，是待办，退回 CLOSED 队列。
> 这条把「挂账」从免责声明变回工作量清单。

**「已证不存在」是 CLOSED 的合法子型**，但必须带证据链（查了哪几册、看到什么构造替代了它），
否则与「没查」无法区分。

**精度纪律**：隔离类词（推定区／不得进报价／暂列）判 FAIL，
说明类词（未计／估算／待核）只出 INFO。同一行常写两件事，一刀切会误报——
ccj 首版 3 处命中误报 2 处，改后 0。这与本技能做 ×1.05 阈值校准时踩的坑同源。

## 3. 取值层级与注记落地（吸收为 H45）

ccj v3.0.3 复盘发现一类比「看不见」更隐蔽的错：**看到了、也写下来了，但没进到数里**。

- **取值层级**：**图注 > 图面实测 > 尺寸链推算**。实测只能补缺或校核（差 >2% 挂 conflict+RFI），
  **禁止用实测覆盖图上已有注记**——那等于用「我量的」否掉「设计写的」。
  实测：梁长取 34.30 覆盖图注 `2x17500 = 35.00`。
- **注记必须落地**：关键注记一旦目视确认，只能三选一 ——
  ① 按注记落数；② 按注记值进推定区且 qty 写「敞口」；③ 证明它属别的构件（须写归属判据）。
  **禁止「按另一个数出量 + 同时挂 RFI」**——挂账不是免责，是把错数留在表里过夜。

对应本技能历史错误：把 `B=3.00` 示例值当定值（洞口防护 234.9 vs 336.1）、
单值替换忽略量纲（+2549%）。**都属于「看到了没进数里」。**

## 4. 图册状态码 → 证据强度封顶（英语图册补齐）

本技能原有法语体系（APS/APD/EXE），英语图册状态码是空白。
`gate_off_table.py status --code <码>` 可查：

| 状态码 | 允许最高强度 |
|---|---|
| `IFT` / `TENDER` / `IFP` / `IFB`（招标/采购） | 图读·尺寸链 |
| `IFA` / `IFR`（报审） | 图读·尺寸链 |
| `SD` / `DD`（方案/初设） | 图读·尺寸链 |
| `IFC` / `CD`（施工图） | 图读·标注 / 图读·量表 |
| `AB` / `AS-BUILT`（竣工） | 图读·标注（**须与实测互证**） |
| `APS` / `APD` / `EXE`（法语） | 尺寸链 / 尺寸链 / 标注 |

判据看图签 `Status:` 或 `Purpose of Issue:` 一行。
**看不到就挂 RFI，不许默认按 `IFC`** —— 默认 IFC 等于把「没确认」写成「已确认」（原则 13）。

英语图册另有同形异义五词（`PAVEMENT` 路面/人行道、`PILE CAP` 承台/盖梁、
`BEARING` 支座/方位、`COVER` 保护层/覆盖、`INVERT` 仰拱/管底标高），
开工前须逐词确认；英制换算（SI↔ft、ASTM #3–#18、NPS↔DN、UB/UC）只用于换算与校核，
**不作取值依据**。

## 5. 只吸收原则、不搬库：工法未定不出量

ccj v3.3.0 最重的一块是**工法判定链**（368 条工法库 570KB + `method_matcher.py` 755 行
+ G19 组门禁）。它的核心洞察有价值，且与本技能「数据源语义误读」同源：

> **工法判错时，表里每一个数都可以是对的。**
> Ø1200 灌注桩用泥浆护壁还是全套管，桩身 m³ 完全一样，
> 但泥浆外运、护筒、超灌三组措施项方向相反；18 道门禁一条都抓不到。

**吸收为一条原则（H48）**：工法判定未收敛（`ambiguous` / `insufficient_info` /
`undetermined`）时，**主体量可出、措施量与工法派生量一律不出**，进敞口台账等回图或 RFI；
**不得自造库里没有的 `method_id`**。

**不搬整套库**，理由三条：
1. 它自己承认 368 条里**只有 41 条是可判定记录**（覆盖一、二册路基路面/桥涵），
   其余 327 条只有原文摘录，`decision_ready:false`，三至八册返回 `undetermined`；
2. 570KB 库依赖 395 份 `.doc` 的 OLE2 二进制解析结果，来源不可在本项目复现；
3. 本技能 21 轮复盘与本轮 8 条实错中**没有一条属于工法类**，投入产出不成立。

> 「参考记录不参与打分」这条倒值得记住：**一个查不到却说「判定成功」的工法，
> 比判不出危险得多。** 这与 G-RUN「没跑不许说通过」是同一个判断标准。

## 7. 元门禁补强：夹具退化也算没跑

ccj 有一条洞察值得单独记下：

> 注入自证此前必须喂真实项目数据，**于是「改判据的那天」恰好跑不了**——
> 而那正是唯一需要它的日子。

本技能 `test_all.py` 已有 23 项 selftest，但缺「**夹具自身是否退化**」这一层。
故 v4.6.3 起：

- `gate_off_table.py selftest` **自带干净夹具**（不依赖任何项目数据），12 用例里
  C1 专门断言「干净夹具不误咬」、C6 断言「无带必须明写未校验」、
  C8 断言「比率带外只指路不定性」——**判据改动当天也能跑**；
- `G-OFF` 已写进 G-RUN 的**三档 required 清单**，`test_execution_receipt.py`
  新增 C7 用例「只漏 G-OFF 一项必须 FAIL 并点名」——
  防止又变成「规则写进技能但没跑也出得了交付物」。

「没跑」和「跑了没抓到」必须分开，否则分母永远是假的。
**没有自带夹具，改判据的那一天恰好验证不了；没有凭证，跑了没跑无法证明。
两者缺一，都等于这条规则不存在。**

## 8. 改进效果怎么验

| # | 指标 | 基线 | 目标 | 怎么测 |
|---|---|---|---|---|
| 1 | 表外缺席在哪个阶段暴露 | 交付/对量阶段 | **开工前 COV 闸门** | 记录每个漏项首次出现在消化/算量/复核/交付哪一阶段 |
| 2 | 「挂账」条目数 | 未统计 | **0**（全落四态） | `gate_off_table.py check` 无 `OI-1` |
| 3 | 未核页数图册占比 | 未统计 | **0**（strict） | `COV-1` 计数 |
| 4 | G-OFF 真实执行率 | — | **100% 有凭证** | G-RUN `verify --strict` exit 0 |

**验收门槛**：`gate_off_table.py selftest` 必须 `用例覆盖 42/42`，
且 `test_all.py` 全绿，才允许在交付物里写「改进已验证」；否则只能写「已实施，效果待观察」。
