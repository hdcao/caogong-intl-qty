# 人工审阅回环（human-review-loop）

**一句话**：AI 出量，人审量——但审的不是"数对不对"，而是**"这个数从哪条尺寸链读来的"**。

---

## 一、为什么必须有这一环

本技能的产出链是单向的：读图 → 填读数四问 → 落表 → 门禁。门禁能查
自洽（公式、口径、单位、跨表），**查不了读图本身**——它不知道 3403.50 CM
是从"10 片 × 0.75 m²"读来的，还是从"9 片 × 1.28 m 间距误当梁宽"读来的。

2026-10-24 对比 openclaude 单遍算量，对方六处结构误读（桩径与墩柱直径对调、
承台与盖梁尺寸串位、多片箱读成单箱、墩柱"双柱 1.20×3.40"）——
**它的自校验一项都没拦**，因为自校验验的是算术，不是读法。
能抓住这类错的只有一件事：**让一个能翻开原图的人，逐行挑战读图的出处。**

对应到质量体系：审阅是 RACI 里 A 的职责（`quality-system.md` §四），
AI 不代签（§五）。本文件是 A 的动作规程。

---

## 二、机制来源与改造点

来源：外部技能族 `pk-boq-review` 的 HTML 审阅稿——用户在浏览器里改、
留痕、AI 读回变更表。**借机制，不借代码**（他们的审阅稿只审"数值与依据是否匹配"）。

**本技能的改造（关键差异）**：审阅稿必须保留 **图号出处 + 图面位置** 两列，
且把缺这两列的行**标红**。理由：

| 审阅稿形态 | 能抓住什么 | 抓不住什么 |
|---|---|---|
| 只审"数 vs 依据文本" | 依据写错、口径词缺失 | 依据本身读错（图和数都错，文本自洽） |
| **带图号+图面位置** | 上述 + **读图错误**（审阅者按图面位置回原图复核） | —— |

缺图号出处或图面位置的行，**不许当作"已审"**——审阅者无法回图，
签的只是"我信你"。这类行先回读图步骤补位置，再进审阅稿。

## 三、怎么用

```bash
# 1. 生成审阅稿（自包含 HTML，可邮件/可拷贝）
python scripts/make_review_html.py <表>.xlsx --sheet 1_成本取量总表 \
    --out takeoff/review_20261024.html

# 2. 人审：浏览器打开，逐行选 确认 / 推翻 / 待补充，推翻必须填改后值与理由
#    （选择与文字存 localStorage，刷新不丢；可中途关闭）

# 3. 点「导出变更表」→ 得到 changes.json（只含被动过的行）

# 4. 先过机器校验（v2.1.2 新增，**机器先拦，AI 后读**）：
#    python scripts/make_review_html.py check changes.json \
#        --xlsx <表>.xlsx --sheet <页签>
#    exit 非 0 就退回去让审阅者补（0=放行 / 1=不合规逐行列出行号+原因 /
#    2=无法运行：坏 JSON / 页签不存在 / 列映射冲突 / 空变更表）；
#    exit 0 才进第 5 步

# 5. AI 读回 changes.json，按 §五 三种落法处置
```

**审阅稿的列**（由 colmap 自动识别，可 `--col role=N` 覆盖）：

| 列 | 来源角色 | 审阅者拿它干什么 |
|---|---|---|
| 编码 | code | 定位（改表时按编码+行号双锚） |
| 名称 / 单位 / 工程量 | name / unit / value | 被审的数 |
| 口径声明 | basis | 范围口径（单幅/全桥/单侧） |
| 图号出处 | draw | **回哪张图** |
| 图面位置 | pos | **看图上的哪儿**（坐标/立面/剖面/COUPE） |
| 证据档 / 依据类型 | conf / evidence | 这条数是图读、推定还是暂定 |
| 审阅结论 | — | 确认 / 推翻 / 待补充 |
| 改后值 + 审阅备注 | — | 推翻时必填；备注即可核查理由 |

小计行（`★合计`、`小计`）只读不审——它们是派生值，审它们等于审公式。

## 四、三条纪律

1. **sheet 身份 =（簿名, 页签名），且由人指定。**
   外部实测教训：两个分包簿都有「1_成本取量总表」，按 sheet 名取表
   **取错簿**，数值差 100 倍而流程全绿。所以：
   - 生成审阅稿时 `--sheet` 必须显式传，不猜、不默认；
   - 审阅稿页眉写明「簿名 + 页签名」双身份；
   - **跨簿汇总前先人工确认 sheet 白名单**（哪几个簿的哪几个页签进汇总），
     白名单本身要写进交付说明。
2. **推翻必须带可核查理由。** 与 ack 台账同标准：少于 8 个字的理由
   （"不对""重算"）不足以让人三个月后复核。以前靠 AI 读回时自觉退回，
   v2.1.2 起**机器先拦**：AI 读回 changes.json 前必须先跑
   `make_review_html.py check`，exit 非 0 就退回去让审阅者补
   （机检四条：推翻缺改后值/理由、row 不在数据行范围、old_value 与
   当前单元格对不上、sheet/表名与实参不符；空变更表直接拒）。
3. **变更表是唯一回读入口。** 对话里说的"我改一下""按 3718 算"不算数——
   没有进 changes.json 的修改，AI 一律视为没有发生。
   这与 F-E06（直接改生成的 xlsx，重跑被覆盖）是同一条纪律的两个人：

   | 谁改的 | 载体 | 后果 |
   |---|---|---|
   | 人改 xlsx | 工作簿 | 下次生成即被覆盖 |
   | 人改 HTML | changes.json | 被读回、落账、可追溯 |

## 五、AI 读回变更表后的三种落法

**AI 读回 changes.json 前，必须先跑 `make_review_html.py check`**（机器先拦，AI 后读）：
exit 非 0 就退回去让审阅者补——exit 1 逐行列出行号+原因，exit 2 是坏 JSON /
页签不存在 / 列映射冲突 / 空变更表。exit 0 才按本节三种落法处置。

| 审阅结论 | 落法 | 落地物 |
|---|---|---|
| **确认** | 写 ack 台账（含数值指纹） | `ack_util` 条目，行被改过会报 ACK-STALE |
| **推翻 + 改后值** | 改生成器 → 重跑 → **重跑全部门禁**（含 G-XST） | 修正台账 + 新 gate_report |
| **待补充** | 挂开放项（APD/RFI），不进成本模型 | 敞口台账，带假设人/确认日期 |

**共同要求**：无论哪种，都要在交付说明里写"本轮人工审阅 N 行，
确认 x / 推翻 y / 待补充 z"。没有这个数的交付物，视为未审。
