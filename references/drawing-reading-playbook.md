# 读图方法技法库（Drawing Reading Playbook）

> 本文回答三个问题：**怎么读**、**什么时候用这个技法**、**用错了会怎样**。
> 每一条技法卡都带"适用条件 / 前置校验 / 失效模式 / 证据强度 / 实测案例"。
> 没有证据强度标注的读数，一律按最低档处理。

## 0. 先判型，再选技法（不要拿锤子找钉子）

拿到一张图，**第一件事不是渲染，是判型**。判错型的代价是整轮白费：

| 文本层 `text` | 扫描 `scanned` | 页面性质 | 常见图种证据 | 首选路线 | 别做的事 |
|---|---|---|---|---|---|
| > 0 | False | 原生矢量 + 真文字层 | 集中标注含 `@` 间距、成组编号 | **T2 文本层解析**（最快最准） | 别急着渲染 |
| > 0 | True | 扫描件 + OCR 文字层 | OCR 层错字率高，须回图核 | T2 检索定位 + **T7 原生 dpi 切块** | 别信 OCR 的数值 |
| 0 | True | 纯扫描栅格 | 只能靠字形与线型判 | **T7 原生 dpi 切块** | 别整页低dpi渲染 |
| **0** | **False** | **文字转曲矢量** | 图元密集但无字符，`@` 也是轮廓线 | **T3/T4 矢量取证 → T5 尺寸链 → T7 渲染** | **别指望 OCR**（转曲后没有字符，OCR 只能认图，救不回来） |

判型命令：

```bash
python scripts/extract_dwg_vector.py <图>.pdf --list      # 判型：text / fonts / 图片（毫秒级）
python scripts/vector_forensics.py probe <图>.pdf --out out/probe.json   # --out 给文件名
```

**判型要点**：`get_text()` 为空 ≠ 扫描件。矢量图没有字体对象、但 `get_drawings()` 有几百上千个图元——这就是**文字转曲**。此时提高渲染倍数、反复 OCR 都没用，因为根本没有字符层。

反过来同样要防：**`text>0` 也不等于"标注都在文字层里"**。文字层可能只含跨号/标高/图名，尺寸标注仍是转曲的。

> 本项目实测（2026-10-23 复核更正）：图册 23041-OVA-29-V0 三张**都有文字层**，
> `text=1237 / 2782 / 10382`（fonts=4/5/10），并非早期记录的 `text=0`。
> 正确路线是 **T2 文本层打底 + T3/T5 图元与尺寸链补缺口**：
> 跨号、标高、`9.60`/`6.00` 等尺寸可从文本层直取（strong），
> 而梁数（10 片/跨 @1.28）、台身楔形（1.00/5.50/6.00）仍要靠图元聚类与尺寸链闭合。
> **教训**：判型结论也要留复核痕迹——一个写错的 `text=0` 会把整条取证路线推到弱证据档。

### 0.2 图种判定：看标注，不看图名（v4.6.0）

**图名 ≠ 图种。** 图名是绘图人写的，标注才是图自己在说话。判错图种，整批漏项：

| 图面证据 | 结论 | 该取什么 |
|---|---|---|
| 出现 `@`（间距符号）、多行竖排集中标注、`HA/FE/Ø + 数量` | **配筋图** | 钢筋规格、间距、根数、锚固 |
| 只有构件编号 + 截面尺寸（`40×60`）、无 `@` | **布置图 / 模板图** | 构件几何、标高、轴线位置；**这里没有配筋** |
| 两者都有，分图框或分区 | 合图（`COFFRAGE ET FERRAILLAGE`） | 分区判读，不能按整张统一处理 |

法语图名对照（判图种时**必须回图核对标注**，不能凭图名直接跳）：

| 图名 | 是什么 | 陷阱 |
|---|---|---|
| `PLAN DE COFFRAGE` | 模板/布置图 | 在这里找配筋 = 整批钢筋漏项 |
| `PLAN DE FERRAILLAGE` | 配筋图 | 别拿它量构件外形（常只画钢筋骨架） |
| `PLAN DE COFFRAGE ET FERRAILLAGE` | 合图 | 两种信息在同一张，须分区落账 |
| `COUPE` / `ÉLÉVATION` | 剖面 / 立面 | 图名常互换（`COUPE` 画的是立面）——按投影方向判，不按名字 |
| `NOTICE` / `NOTE DE CALCUL` | 说明 / 计算书 | 数值以说明为准时常与图形不一致，进跨图校验 |

> **在布置图上找配筋，是整批漏项的开始**；反过来在配筋图上量外形，会得到偏小的断面（钢筋骨架不等于构件轮廓）。

## 1. 三条通用纪律（任何技法之前）

### 纪律一：比例尺必须**双校准**，不能只量一次

单一次标定出错无从发现。**必须找到两个已知尺寸互相印证**：

```
本项目 C.1 台区立面（3/3 张 page 2）标定：
  ① 承台填充矩形 108.6 pt ÷ 9.58 m = 11.33 pt/m
  ② 承台厚度   25.0 pt ÷ 2.20 m = 11.36 pt/m
  两者互证 → 取 11.33 pt/m（差 0.3%，在容差内）
```

若两个值差超过 2%，说明**量错了对象**（量的不是同一个构件，或含了箭头外延），必须重找参照。

**但双校准有一个它挡不住的失效模式：整页等比缩放。**

两个参照来自同一张图，一旦整页被等比缩放（A0 打印成 A3、扫描仪 600→300 dpi 重采样、
`UserUnit`/`CropBox` 变化、微信转图压缩），两个参照会给出**完全相同的错误 pt/m**，
互证 100% 通过——而全图实际偏 29.3%，面积偏 50%。上面那个 11.33 / 11.36 的例子，
两个参照就在同一页上，正好是这个盲点。

所以双校准必须配**绝对尺寸锚**，三条缺一不可：

| # | 做法 | 为什么 |
|---|---|---|
| 1 | 两个参照**跨尺度**（≥1 个数量级，如 0.5 m 级配 50 m 级），尽量跨图册 | 同尺度同页的两个数会一起错 |
| 2 | 核对**图框标准尺寸**（A0 = 841×1189 mm、A1 = 594×841 mm…）或图上**比例尺条**的实际长度 | 这是唯一能发现"整页缩放"的手段——它不随图内容缩放 |
| 3 | 图签含 `NOT TO SCALE` / `SANS ÉCHELLE` / 不按比例 → **禁止任何图面量测** | 设计已经声明这图不能量，量了就是自造数据 |

阈值也改成双阈值 **`max(2 mm, 0.2%)`**：纯 2% 对 12.9 m 的构件是 258 mm（会放过漏一个 200 mm 的边），
对 456 m 的桥长是 9.1 m（会放过少算一个缩短段）；纯绝对值又会对 1.25 m 的详图判假红。

**常备比例尺参照**（按可靠度排序）：
1. 填充/剖面线矩形（实体构件，边界确定）
2. 标注尺寸线（注意：含箭头外延，须扣除）
3. 图签比例栏文字（需有文本层）
4. 同一图册其他图的同构件（交叉验证）

### 纪律二：方向必须先判，再取值

**图上有这个数 ≠ 这个数回答了你要问的问题**。取值前必须确认三件事：

1. **量的是哪个方向**：纵向（沿路线）/ 横向（垂直路线）/ 竖向 / 斜向
2. **描述的是谁的什么属性**：宽 / 高 / 厚 / 长 / 间距 / 数量
3. **单位与量纲**：m / m² / m³ / kg / t / 个 / 座 / 根 / 片 / 道 / 套

**斜交桥红旗词**：出现 `SKEW`、`MEASURED ALONG THE SKEW`、`SLOPE %`、`OFFSET` 时，图上所有尺寸都要问"按哪个方向量"。沿桥轴结构长与沿路线路线长差 **1/cos θ**。

**实测事故**：某桥桥面宽写 26.0 m，出处 "1194+23610+1194=25998"。25998 确实在图上、确实是这个构件的尺寸——但它是**纵向梁区总长**，不是横向桥面宽。真值 15.75 m，修正 **−39.4%**。

### 纪律三：编号序列要查重，不要默认只有一组

遇到 `A1-P1-P2-P3-A2` 这类完整序列，先问**它在别处是否重复出现**。

**双幅/上下行/分线设计里，两幅常常共用同一套桩号。**

两条独立证据可确认"两幅各有独立结构"：
1. 基础平面图桩符号排成 **3 行 × 8 列**点阵，x 方向分成**两组各 4 列**（组内间距 55.1 pt、组间 180.1 pt，组间是组内 3.3 倍）= 两排承台
2. 总平面图上**同一桩号出现两次且标高不同**

> 实测：某桥按 3 个承台算，实为 **6 个**（南北双幅，每幅各有独立的 A1-P1-P2-P3-A2）。

## 2. 技法卡

### T1 · 比例尺标定（双校准法）

| 项 | 内容 |
|---|---|
| **适用条件** | 图面无明确比例尺，或需要用图面量测反推尺寸（桩位间距、符号数量、构造厚度） |
| **不适用** | 图上有完整尺寸链时——优先直读标注，不要把量测值当图读值 |
| **前置校验** | 至少两个已知尺寸的构件；确认量测对象**不含箭头外延/引出线** |
| **失效模式** | ① 只量一次，错了不知道；② 把尺寸线总长当构件长；③ 旋转图未回正就量 |
| **证据强度** | `chain_derived`（若用于闭合反算） |

**步骤**：找两个已知尺寸 → 各自算 pt/m → 差值 <2% 才采信 → 记录标定值与两个参照构件 → 后续所有量测都用这一个尺。

---

### T2 · 文本层解析

| 项 | 内容 |
|---|---|
| **适用条件** | `text > 0` 且 `scanned=False`（原生矢量 + 真文字层）；配电盘回路表、构件表、材料表 |
| **不适用** | 文字转曲（text=0）；扫描件 |
| **前置校验** | 先跑一页看有没有"没有单位的裸规格"；确认 `get_text("words")` 能按 y 重组行 |
| **失效模式** | 见下方三坑 |
| **证据强度** | `text_layer` |

**三个解析坑**（实测都踩过）：

| 坑 | 现象 | 防护 |
|---|---|---|
| **分词截断** | `4Cx35mm` 与 `4Cx35mm2` 混排（上行末尾被截断到下行） | 正则写 `mm2?`；规格写 `4C[xX](\d+)mm2?$` |
| **行序错乱** | `get_text("text")` 按 PDF 流顺序输出，**不保证阅读顺序** | 用 `get_text("words")` 按 y 坐标重组行；构件表**必须按列坐标对齐** |
| **一页多表** | 一张图排了两个配电盘（实测 10 张图覆盖 FP-01~17） | 先定位所有表头行的 y 坐标，再按"最近的上方标题"归属每行 |

> **本项目最硬的一条教训**：PDF 文本流顺序 ≠ 表格行列顺序。
> 一次把构件表按阅读顺序串行，导致 9 类构件数量全部错位。
> **构件表必须按列坐标（x 值）对齐，不要按阅读顺序。**

解析器必须输出**可累加的结构化记录**，并打印按规格与按盘柜的汇总，便于与人工抽点对照。**不要靠肉眼加起来。**

### T3 · 矢量图元提取与三张直方图

| 项 | 内容 |
|---|---|
| **适用条件** | 文字转曲矢量图；需要**数个数**（桩、支座、灯杆、符号）但文本层不可用 |
| **不适用** | 纯扫描（无矢量图元） |
| **前置校验** | 先 `probe` 看 `get_drawings()` 图元数量级（几十个太少，几百上千才有统计意义） |
| **失效模式** | 图例区污染计数；虚线短划被当成符号 |
| **证据强度** | `vector_cluster` |

```python
for dr in page.get_drawings():
    fill = dr.get("fill"); stroke = dr.get("stroke")
    for it in dr["items"]:            # ("l", p1, p2) / ("re", rect) / ("c", ...)
        ...
```

**三张直方图及其用途**：

| 直方图 | 用途 | 实测案例 |
|---|---|---|
| **填充色 `fill`** | 按颜色分离图元类别（设计院常用固定配色） | 照明布置图灯头 = `(1,0,1)` 品红；手孔 = `(0,0,1)` 蓝；人孔 = `(1,0,0)` 红 |
| **矩形尺寸** | 区分符号与线条碎块（长宽比 >3 多为虚线短划） | 灯头方块 2.0/3.0/3.8 pt |
| **线段角度** | 判构件走向、找主要方向 | 梁线为竖向虚线；尺寸线水平 |

**颜色语义速查**（国际工程常见，但**必须以图例为准**）：

| 颜色 | 常见含义 |
|---|---|
| 红 | FSR 纵坡线 / 轴线 / 人孔 |
| 青 | 盖梁 |
| 蓝 | 台身楔形 / 冲刷包络 / 手孔 |
| 绿 | 地形线 |
| 灰 | 剖面线 / 图案填充 |
| 品红 | 灯头 / 设备符号 |

### T4 · 颜色 + 尺寸过滤 + 空间聚类计数

| 项 | 内容 |
|---|---|
| **适用条件** | 符号按**规则阵列**排布，且颜色/尺寸可区分（桩位、灯杆、支座符号） |
| **不适用** | 符号无规律散排；符号与底图同色同尺寸 |
| **前置校验** | **tol 必须标定**（见下）；图例区必须排除或减常数 |
| **失效模式** | tol 太小 → 一个符号被拆成多个"1 头"（计数虚高）；tol 太大 → 相邻符号合并（计数偏低） |
| **证据强度** | `vector_cluster` |

**流程**：
1. 按 `fill == 目标色` 取全部图元矩形
2. **方形/尺寸过滤**：`wmin≤w≤wmax`、`hmin≤h≤hmax`、`aspect_min≤w/h≤aspect_max`，剔掉虚线短划与转曲碎笔画
3. 取每个矩形**中心点**，空间聚类（并查集 / KDTree，阈值 `tol`）
4. 输出**"每簇块数"直方图** —— 这就是"每个符号含几个计量对象"

**`tol` 标定方法（成败关键）**：
```
先量：① 符号内相邻块中心距   ② 相邻符号中心距
取二者之间的值
实测（照明图）：符号内块距 ≈ 4 pt，相邻杆间距 ≈ 60 pt → tol = 6 安全
```

```bash
python scripts/vector_forensics.py symbols <图>.pdf \
  --color 1,0,1 --size 1.9-4.5 --aspect 0.75-1.33 --tol 6 --out out/
# -> {"total_symbols": 21, "hist": {"1": 6, "2": 3, "3": 2, "6": 1}}
```

> **图例区污染**：每页右栏图例里也画着同样的符号。要么裁掉图例区再统计，
> 要么减去图例常数，**并把做法写进 provenance**。

### T5 · 尺寸链闭合反证（最有力的交叉验证）

| 项 | 内容 |
|---|---|
| **适用条件** | 任何"靠数数得到的量"（梁、桩、灯杆、涵孔、支座） |
| **不适用** | 尺寸链本身不完整的图（此时应挂 RFI，不要凑） |
| **前置校验** | 先确认所有分段尺寸属于**同一方向、同一基准** |
| **失效模式** | 把纵向链与横向链混着求和 |
| **证据强度** | `chain_derived` |

**读到的每一组尺寸都要能闭合。闭合不了，先反证，不要先认错——但也不要硬凑。**

原文写的是"闭合不了就是判读错了，不是图纸矛盾"。这句话把不闭合的**唯一原因**指定为
"我读错了"，而真实图纸上不闭合是常态，至少六种原因里有五种不是读错：

1. 分段取整（`3.30+3.30+3.30=9.90`，总长标 `9.89`）——法语/北非图纸的日常；
2. 建筑与结构基准不同（轴线到墙面含 20 mm 抹灰，结构边线不含）；
3. 总尺寸含变形缝宽度，分段不含；
4. 局部修改图只改了一段，总尺寸没跟着改（最常见的设计错）；
5. 尺寸链本来就是示意性的（方案图、招标图）；
6. 剖面切在收坡/斜墙上，图面量测不闭合但设计是对的。

把 2~6 全归因于"读错了"，会逼人重读到"闭合"为止——最后一定是把误差压进某一段
最不可核的尺寸。**"不许取中间值凑"这条（见后）与"闭合不了就是读错了"是互相打架的，
而先读到的是后者。**

正确顺序：

```text
① 重读该段（最常见是漏看一段、把相邻标注挂错构件）
② 换一张图交叉（平面/剖面/详图里同一个数）
③ 检查是否属于上面 2~6 类（取整 / 异基准 / 含变形缝 / 改图未同步 /
   示意尺寸链 / 剖切位置在斜面）——这三类不是错
④ 三次仍不闭合 → 判图纸矛盾，挂 RFI，**两值都留**，不许二选一
```

**"不闭合"是证据，不是罪名**——它既可能是读错，也可能是设计错，区分二者正是 QS 的活。

```bash
# 分段求和
python scripts/vector_forensics.py chain --total 19960 --parts 1630,1630,...
# 均分反算：N = (L总 − 2×边距 − 单件宽) / 间距 + 1
python scripts/vector_forensics.py chain --total 23610 --equal 8 --edge 1194 --unit 1640
# 实测：桥2 (23610 − 2×1194 − 1640)/2448 + 1 = 9 榀/幅，与 "8 EQUAL SPACES" 一致
```

**闭合类型**：
- **分段求和**：`19960 = 11 × 1630` → 12 榀梁
- **均分反算**：见上式
- **标高/厚度闭合**：箱涵总高 `2400 = 450(底) + 1500(净空) + 450(顶)`
- **高程链闭合**：`FSR − 承台底 = 承台 2.20 + 柱高/台身 6.00 + 盖梁 2.00(墩) + 支座 0.283 + 梁 2.00 + 板 0.30 + 道床 0.80`

> ★ **凡是要靠"数数"得到的量，都必须有一条尺寸链或一张专用表兜底。**
> 只用视觉数数的，一律降为 `medium` 并挂 RFI。

**反证不通时的处理顺序**：
```
重读图（多半是漏看一段尺寸链）→ 换一张图交叉 → 标 conflict 挂 RFI
```
**不许取中间值"凑"。**

### T6 · 专用表直读（禁止推算）

| 项 | 内容 |
|---|---|
| **适用条件** | 图纸上有专用表：支座表、桩位图、钢筋表（BBS）、图例（LEGEND）、构件表 |
| **不适用** | 无表可查 |
| **前置校验** | 确认表是**单幅**还是**全桥**（看标题栏 `SOUTHBOUND/NORTHBOUND` 等限定词） |
| **失效模式** | 用"幅×跨×片×端"推算支座/伸缩缝 |
| **证据强度** | `schedule_direct`（最强） |

**为什么推算法必错**：支座在墩上**不与梁片一对一**。
实测：某桥单幅 12 片梁，墩上却有 18 个支座；模型侧按 `4 × 跨数 × 梁片数 × 2端` 算得 96，支座表是 72。
斜交桥尤其如此——支座布置由受力与变形需求决定，不由梁片数决定。

**规则**：
1. 支座、伸缩缝这类**数量由专用表给出的项，一律直读该表**，不推算
2. 图上 `TOTAL NUMBER OF BEARINGS (L×W×H)` 这类表是权威源
3. **区分单幅数与全桥数**：图名是单幅图时，表里的数是单幅数（要 ×2 才是全桥）
4. 反推不通就别硬推（曾试"由支座数反推梁片数" 84÷3÷2=14 片，但与图注 3000 c/c 矛盾 → 改按构造定并标为假设）

**可反推关系**：

| 专用表 | 可反推 | 实测式 |
|---|---|---|
| **支座表**（AT ABUTMENTS / AT PIERS） | 梁数、跨数、幅数 | `192 = 4 跨 × 2 幅 × 12 榀 × 2 支座/榀` |
| **桩位图**（P1~P12） | 桩数、承台数 | `每台每幅 6 根 Ø1200` |
| **图例** | 杆型种类、每杆灯具头数 | `6 个方块 = 1 座 25m 高杆 + 6 套灯具` |
| **钢筋表** | 单座基础钢筋量 | `1,233 kg/座 × 526 座` |

### T7 · 渲染切块读数（主力取证手段之一，v4.6.0 重写）

> **改口径的原因**：v4.5.3 把渲染切块定为"最后手段"、`render_read` 一律 weak→挂 RFI，
> 等于说"看图读数字不可靠"。但国际工程现实相反：A0 图缩印成 A4 的 PDF、法语 8pt 标注、
> 文字转曲的矢量图——**这些图上最可靠的办法恰恰是高倍切块把数字读出来**。
> 把"读到明确数字"和"目测估长度"并作一档，会把人逼去向尺寸链要量，
> 而尺寸链的前提（关系读对）本身就是弱项（G-CHAIN 就为此而设）。
> 所以拆成两档：**读到字的算 medium，没字可读的才是 weak**。

| 项 | 内容 |
|---|---|
| **适用条件** | ① 无文本层/文字转曲/扫描件；② 有文本层但尺寸标注转曲；③ 需确认构造做法或定性判断 |
| **不适用** | 专用表（T6）、文本层（T2）能直取的场合——不是"不能用"，是"有更强的就不用这条" |
| **前置校验** | 必须先建坐标系（见下 §T7.1 两遍法），**禁止未建坐标系就切块** |
| **失效模式** | 硬边界截断多行标注；中间 tile 猜轴号；把 A4 物理尺寸当"不用切块"的理由 |
| **证据强度** | 读到字 `render_read_text` = **medium**；无字可读 `render_read_est` = **weak → 必须挂 RFI** |

#### T7.1 两遍法（强制顺序）

| 遍 | 做什么 | 产出 | 禁止 |
|---|---|---|---|
| **第一遍：低成本全图** | 定图种、判轴线方向、找标注密集区、划有效区边界（去掉图签/图例/空白） | 一张全局缩略图 + 轴线清单 | 禁止在这一遍取任何数值 |
| **第二遍：按方案切块精读** | 按轴线或网格切块，逐块读数 | tile 图 + 读数 + 坐标 | 禁止跳过第一遍直接切 |

**判据**：第二遍的每个读数，其 `location` 必须能只靠 manifest 复原到唯一 tile 与 tile 内坐标。
做不到 = 这一遍不合格，读数不可交付。

#### T7.2 切块纪律（五条，全部可判定）

| # | 纪律 | 判据 | 违反后果 |
|---|---|---|---|
| 1 | **15% 重叠** | tile 之间重叠 ≥ tile 短边的 15%，**禁止硬边界** | 任何标注块只要不超过 tile 宽 30%，至少在一个 tile 内完整出现——这是可证明的，不是经验值 |
| 2 | **优先沿轴线切** | 每个 tile 覆盖 1~2 个柱网格 + 两侧重叠；轴线不清才退等距网格 | 沿轴线切，读数可挂到轴号上；网格切只能挂到像素 |
| 3 | **尺度统一 3.0** | 全部 tile 用同一 `scale=3.0`，**不做 2.0/3.0 分级判断** | "按密度取倍数"是引入了不可靠的人工判断；实测 3.0 对小字场景提升 38%~65%，代价约 3 秒/页 |
| 4 | **字高 ≥10 px（按 p10 判）** | 测 tile 内标注字高的 **p10**（不是 min），<10 px 该 tile 判不通过，须再切小或升 scale | 字高不足时读出来的数字是猜的，不是读的。**用 min 判会假红**：见下方实测 |
| 5 | **轴线像素映射表落盘** | 输出 `tiles/manifest.json`，后续所有定位只查表 | 中间 tile 猜轴号 → 后面全错（本项目 B-新3 案例） |

**工具**：

```bash
# 建 manifest（重叠切块 + 字高测算 + 轴线映射）
python scripts/render_tiles.py build --pdf <图>.pdf --page 2 --scale 3.0 --overlap 0.15 \
        --axes "A:320,E:1180" --out tiles/
python scripts/render_tiles.py check --manifest tiles/manifest.json --min-glyph 10
# exit 0 通过 / 1 存在字高不足或重叠不足的 tile / 2 参数或文件问题
```

`manifest.json` 每条至少含：`tile` 路径、`page`、`bbox`（pt）、`scale`、`glyph_px`（推算最小字高）、`axes`（覆盖轴号区间）、`overlap_ok`。

#### T7.2.1 实测：字高判据为什么按 p10 而不是 min（2026-11-02，本项目图册第 1 张）

| 量 | 值 | 说明 |
|---|---|---|
| 整页字号样本 | 118 个 span | — |
| 最小字号 | **3.14 pt**（仅 1 个） | 图签/脚注类孤立小字 |
| p10 字号 | **7.85 pt** | 真正的标注字号 |
| 中位数 | 11.77 pt | — |

- 按 **min** 判：3.14 × 3.0 = **9.4 px < 10** ⇒ 6 块里 **2 块判死**，但其中一块 p10 = 23.5 px，
  字清清楚楚——**这就是假红**。图签小字把所有块判死，跑两次没人再看这条判据。
- 按 **p10** 判：6 块里 1 块 FAIL（该块 p10 = 9.4 px，整块字都小，是真红）、1 块 WARN
  （孤立小字，已提示）、5 块通过。
- **处置验证**：把那块 `--scale` 从 3.0 提到 **4.2** 重切 → 6/6 通过，WARN 仅剩图签小字一条。
  说明"字高不达标就升 scale"这条处置是有效的，不是写给人看的。

**结论**：判据默认 p10，min 单列在 `manifest` 里备查（`--stat min` 可切回最严口径）。
**同一条纪律**：假红比假绿更耗人——出现过一次，整条判据就会被跳过。

#### T7.3 判读顺序与取数规则

- **判读顺序**：图签 → 图名 → 图例 → 尺寸链 → 断面 → 明细表（先定这张图是什么，再取数）
- **只读字，不量图**：tile 里有数字就读数字；没有数字才量像素，且必须转 `render_read_est`
- **多行集中标注必须整块可见**：若某块跨 tile，把相邻两块一起看，**不许只根据一块拼结论**
- 扫描件按**原生 dpi** 渲染，超原生 dpi 只插值不提清晰度

#### T7.4 反模式（都是真出过事的）

| 现象 | 根因 | 防护 |
|---|---|---|
| 整批漏读某行标注（不是读错，是没读到） | 硬边界切块把多行竖排集中标注截断，下部通长筋/侧面筋整行丢失 | 15% 重叠 + 沿轴线切 + 字高 ≥10px |
| 因"这页是 A4"判定无需切块 | 把**物理尺寸**当成触发条件 | 触发条件是**信息密度与字高**，不是幅面；A4 缩印 A0 图恰恰最需要切 |
| 中间 tile 猜轴号，后续全错 | 未建轴线像素映射 | 必须追到边缘 tile 读圆圈编号，禁止在中间块推断 |
| 大样图器具数 × 未确认的重复次数 | 标准单元倍增缺"重复次数"图证 | 重复次数必须在平面图逐层点出并单独记行，不得引用"标准层×N" |

## 4. 证据强度字段（`method` / `evidence_word`）规范

每条读数必须登记**两个口径维度**：

| 维度 | 字段 | 取值 |
|---|---|---|
| **这个数哪来的** | `evidence_word` | 图纸确认 / 推算 / 估算 / 待核 |
| **怎么取出来的** | `method` | 六档，见下表（v4.6.0 起 `render_read` 拆为 text / est 两档） |

**方法 → 证据强度映射**：

| method | 中文 | 强度 | 硬性要求 |
|---|---|---|---|
| `schedule_direct` | 专用表直读 | strong | — |
| `text_layer` | 文本层解析 | strong | — |
| `chain_derived` | 尺寸链闭合 | medium | 必须有计算式（可复算） |
| `vector_cluster` | 矢量聚类计数 | medium | 必须有计算式（可复算） |
| `render_read_text` | 切块读字 | **medium** | 必须记 tile 坐标 + 字高；缺则判 FAIL |
| `render_read_est` | 渲染估读 | **weak → 必须挂 RFI** | 必须写证据去处（RFI/台账/清单/图号） |

**旧写法迁移**：v4.5.x 台账里的 `render_read` 一律按 `render_read_est` 计（**从低不从高**）。
不批量改历史 CSV——改历史记录等于篡改证据链；`drafter_qto.py check` 读取时归一化并报 WARN。

**审图人视角**：`render_read_est` 要重点复核；`render_read_text` 只需核 tile 坐标是否指对位置
（数值本身是读到的字，不再是估的）；`schedule_direct` 才可直接采信。
**没有 `method` 字段的读数 = 没有出处，不许进入合计。**

## 5. 适用条件与免责边界

| 情况 | 处理 |
|---|---|
| 图上有完整尺寸链 | 直读，**不要**用图面量测值冒充图读值 |
| 图上无尺寸但有比例尺 + 可量测 | T1 双校准后可作 `chain_derived`，**须记录标定参照** |
| 图上无尺寸也无比例尺 | 挂 RFI，**禁止用"经验值/常规做法"填数** |
| 数量类（支座/伸缩缝/桩）无专用表 | 挂 RFI，**禁止按"幅×跨×片×端"推算** |
| 两源（图注 vs 图面）矛盾 | 标 `conflict`，两条都留，**不许二选一** |
| 同一构件在两张图上断面不同 | 先确认是否"逐座设计"，**不要挑一个** |

## 6. 与门禁的衔接

读图阶段的产物最终要过三道机器门禁：

| 读图产出 | 门禁 | 抓什么 |
|---|---|---|
| `单位列` vs `口径声明文本` | `gate_dimension_wording.py` (G-DW) | **跨列量纲矛盾**（A02 型事故） |
| `口径标识列` / `依据类型列` | 同上 | 范围口径缺失 / 证据强度缺失 / 禁用词 |
| 落到算量表后的量 | `gate_drawing_basis.py` (G-E) | 量与基准是否相符 |
| 建了模型后的量 | `xcheck_model_vs_2d.py` (G-X0) | 两侧是否**不同源**（全一致 = 共模错误指纹） |

**判据强度只能靠注入验证**——写完觉得"够严"不算数。
`gate_dimension_wording.py selftest` 自带元门禁，捕获率必须 100%。
