# 绘图员负责算量（Drafter-owns-QTO）机制

> **一句话：读数的责任人，必须是亲手在图元上定位过那个数的人。**

---

## 1. 为什么要有这个机制

算量错误按来源分两类：

| 类型 | 占比 | 特征 | 靠什么抓 |
|---|---|---|---|
| **算术错误** | 少数 | 式子对、加减乘除错 | 独立复算、公式门禁 |
| **读数错误** | **多数** | **算术全对**，错在"这个数回答的不是你问的问题" | **只能靠人，靠责任到人** |

读数错误的典型形态：

- 图上有这个数，但它量的是**纵向**，你要的是**横向**（实测 −39.4%）
- 图上是**梁间距 1.28**，你当成**梁宽**（实测 +131%）
- 表头写**"承台顶"**，实际给的是**承台底高程**（整条高程链错位）
- **双幅桥**只数了一排（少算一半）
- 图上 0.45 是**背墙局部厚度**，你当成**台身厚度**（实测 −86%）

**共同点**：每个数都"有出处"，每个式子都"算得对"，错的是**读数这个动作本身**。

而唯一有资格判定"这个数到底是不是我要的那个"的人，是**亲手在图元上定位过它的人**。

---

## 2. 传统分工的失效模式

常见做法是"绘图组出图 / 算量组提量"，中间靠图纸传递：

```
绘图组 ──图纸──> 算量组 ──量──> 造价组
```

失效点：

| 失效 | 后果 |
|---|---|
| 算量的人没画过这张图 | 不知道哪个标注属于哪个构件，只能"猜归属" |
| 绘图的人不知道自己的图被怎么读 | 图面表达（如"承台顶"实为底）的错误无人纠正 |
| 出错后两边互推 | "图上就是这么标的" / "我按图读的" |

**本机制的修正**：把"画图"与"读数"**合并到一个责任人**，切断推责链条。

---

## 3. 机制定义

### 3.1 核心原则

> ★ **读数的责任人 = 建模/绘图的人。复核人只能复核，不能代填。** ★

具体含义：

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| **绘图员（Drafter）** | 落账读数、标注出处、签名 | 不能让复核人替自己填数 |
| **复核人（Reviewer）** | 质疑、要求回图重取、否决 | **不能直接改写读数**（改写即变成新责任人） |
| **批准人（Approver）** | 签字放行 | AI 不代签；签发栏输出 `＿＿＿＿＿＿` |

**关键**：复核人若直接改了数，**他就成了新的绘图员**，必须改签名栏。
这条防止"复核人随手一改，责任还挂在原绘图员名下"。

### 3.2 四条硬纪律

**纪律一 · 一图一签**
每张图的每条读数都要落账：图号 + 图面位置 + 方向 + 口径。
没有落账的读数 = 没有出处 = 不许进合计。

**纪律二 · 读数四问**（下笔前必须能答）

| 问 | 必须答出 |
|---|---|
| ① **在哪** | 图号 + 图面区域/坐标（如 "C.1 台区立面 x642~654"） |
| ② **什么方向** | 纵向 / 横向 / 竖向 / 斜向 |
| ③ **谁的什么属性** | 构件名 + 属性（宽/高/厚/长/间距/数量） |
| ④ **是不是我问的** | 这个数回答的是不是这一行要问的问题 |

四问答不全 → 不许落账。

**纪律三 · 方法分级**
每条读数记 `method`（v4.6.0 起六档），弱证据（`render_read_est`）自动降置信并强制挂 RFI；
`render_read_text`（切块读到图面数字）为 medium，但必须带 tile 坐标 + 字高，否则判 FAIL。
审图人看 `render_read_est` 要重点复核；看 `render_read_text` 只需核 tile 坐标指对了位置。

**纪律四 · 改数回图**
任何数值变更**必须回图重新取证**，不接受"上一版是这么定的"。
变更记录要写明：**原值 / 新值 / 原判读为什么错 / 新证据在哪**。

### 3.3 读数台账（交付物）

字段（见 `scripts/drafter_qto.py` 的 `HEADER`）：

| 列 | 说明 |
|---|---|
| `reading_id` | 编号，**累积不重排、不复用** |
| `cbs_code` | 归属 CBS 编码 |
| `item_name` | 细目名称 |
| `sheet` | 图号/页 |
| `drawing_location` | **图面位置**（区域或坐标） |
| `direction` | **方向/维度** |
| `object_name` | **所属构件** |
| `attribute` | **属性**（宽/高/厚/长/间距/数量） |
| `method` | 取证方法（六档，见 `drawing-reading-playbook.md` §4） |
| `span_word` | 范围口径（全桥/单幅/两侧…） |
| `evidence_word` | 证据强度（图纸确认/推算/估算/待核） |
| `value` / `unit` | 读数与单位 |
| `formula` | **可复算的计算式** |
| `source_ref` | 证据去处（RFI/台账/业主清单编号/规范条款号） |
| `drafter` | **绘图员签名（必填）** |
| `date` / `note` | 日期 / 备注 |

### 3.4 自检规则（`drafter_qto.py check`）

| 码 | 级别 | 抓什么 |
|---|---|---|
| `DRAFTER-Q` | FAIL | 读数四问缺项 / 缺 CBS 编码 |
| `DRAFTER-M` | FAIL / WARN | method 非法；`render_read_est` 无证据去处 → FAIL；`render_read_text` 无 tile 坐标/字高 → FAIL；旧写法 `render_read` → WARN（按 est 计） |
| `DRAFTER-SPAN` | FAIL | 缺范围口径词 |
| `DRAFTER-EV` | FAIL | 缺证据强度词；`估算/推定` 无可核查去处 |
| `DRAFTER-DIM` | FAIL | **单位列量纲 vs 文本复述量纲矛盾** |
| `DRAFTER-BAN` | WARN | 伪闭环词 |
| `DRAFTER-SIGN` | FAIL | 缺绘图员签名 |
| `DRAFTER-ID` | FAIL | 编号重复 |
| `DRAFTER-EMPTY` | FAIL | 台账为空 |

## 4. 岗位定义：PG-11 绘图员 / 建模算量岗

并入 `references/quality-system.md` 的十岗，扩为**十一岗**：

| 岗 | 名称 | 只能看什么 | 明确不看（→谁） |
|:--:|---|---|---|
| **PG-11** | 绘图员 / 建模算量岗 | **图元与标注的对应关系**、读数落账、构件几何与横向/纵向落位、构造做法的图上依据 | 单价、合同条款、税务（→04/06/08）；结构体系判定（→01） |

**PG-11 的否决条件**（有且只有一条）：
> 任何一条进入合计的读数，若绘图员无法当场指到图面上的具体位置，PG-11 有权拦下整行。

这条是唯一的——其他岗都管不了"这个数在图上哪儿"。

## 5. 与读图技法库的衔接

绘图员读数时按 `references/drawing-reading-playbook.md` 选技法：

```
① 判型（text / scanned）        → 决定走文本层还是矢量
② 找比例尺参照，双校准          → T1
③ 优先直读专用表（支座/桩位/钢筋）→ T6
④ 无表时走尺寸链闭合反证         → T5
⑤ 仍不行才渲染切块目测           → T7（弱证据，必挂 RFI）
⑥ 落账：四问 + method + 两类口径 + 签名
```

**禁止跳步**：直接跳到 ⑤（渲染目测）是最常见的偷懒路径，
它把所有强证据降级成了弱证据，且事后无法追溯。

## 6. 脚本用法

```bash
# ① 建册（按分部）
python scripts/drafter_qto.py new --out takeoff/register/ --package 桥梁

# ② 登记读数（四问 + method + 两类口径 + 签名，缺一不可）
python scripts/drafter_qto.py add --file takeoff/register/readings_桥梁.csv \
  --code CBS-OVA-I03 --item "桥台台身混凝土" \
  --sheet "23041-OVA-29-V0/3-3" --location "C.1 台区立面 x642~654" \
  --direction 纵向 --object "桥台台身" --attr "楔形 顶1.00/底5.50/高6.00" \
  --method chain_derived --span 全桥 --evidence 推算 \
  --value 503.10 --unit M3 --formula "2×(1.00+5.50)/2×12.90×6.00" \
  --drafter 曹工 --date 2026-10-21

# ③ 自检
python scripts/drafter_qto.py check --file takeoff/register/readings_桥梁.csv

# ④ 与道桥开项清单比对报漏项
python scripts/drafter_qto.py coverage --file takeoff/register/readings_桥梁.csv
```

## 7. 与其他机制的边界

| 机制 | 管什么 | 不管什么 |
|---|---|---|
| **绘图员负责算量** | 每个读数**有没有人能指到图上** | 单价、合同条款 |
| 口径二维（范围 / 证据强度） | 每个读数**覆盖多大范围、准不准** | 谁取的这个数 |
| 门禁 G-E / G-DW | 量与基准/跨列是否自洽 | 图面判读本身 |
| 交叉复核 G-X0 | 两侧是否**不同源** | 单侧的读数正确性 |

四者**正交不替代**：绘图员责任制解决"人"，口径二维解决"描述"，
门禁解决"结构"，交叉复核解决"同源"。
