# 计量标准与规则优先级（Measurement Standards & Rule Precedence）

> **一句话立场**：计量标准不是"挑一个用"，而是**先登记、再排优先级、冲突时挂账**。
> 标准清单必须可插拔（新项目能加、旧版本能换），优先级链必须能判定（冲突时不许二选一）。
>
> 读本文的时机：**选定/更换计量标准时、两条规则打架时、定单位与取整口径时、开工前建册时**。

---

## 1. 计量规则的五槽模型（标准无关的原语）

任何标准下的任何一条计量规则，都拆成同样的五个槽位。**先拆槽，再谈标准**——
多数"计量规则冲突"其实是槽位没对齐（一个说总量、一个说净量）。

```json
{
  "rule_id": "CESMM4.F.2.1.FORMWORK",
  "standard": "CESMM4",
  "object": "桥台台身模板",
  "unit": "m2",
  "basis": "developed_area",
  "deduct": [{"kind": "opening", "min_area": 0.5}],
  "add": [{"kind": "upstand", "affects": "area"}],
  "merge": [],
  "description_template": "{部位} {grade} 混凝土模板，展开面积计",
  "applicable": {"discipline": "bridge", "region": "*", "version": "*"},
  "priority": 50,
  "source": {"doc": "合同计量前言 §3.2", "clause": "Preambles §3.2", "asof": "2026-10-21"}
}
```

| 槽位 | 含义 | 本项目常见写法 |
|---|---|---|
| `object` | 计量对象（构件类） | 与台账 `object_name` 对齐 |
| `unit` | m / m2 / m3 / kg·t / nr / item / sum | `M3` `M2` `MT` `LM` `EA`（单位符号须归一，见 §5）；`CM` 只有经项目审批映射后才可作为单位别名 |
| `basis` | gross / net / centerline / 展开面积 / 投影面积 / nominal | **必须写明**，这是口径的主要载体 |
| `deduct` / `add` | 扣减与加算（**带阈值**） | 阈值来自项目规则，**不来自标准默认值** |
| `merge` | 附属件是否并入主体（如垫石是否并入承台） | 本项目一律**不并**，另起一行（见 `appurtenance-pairing.md`） |
| `description_template` | 项目名称/特征怎么组织 | 与 `资产样板` 的 `名称` 列一致 |

**置信度**：一条规则的可用置信度 = min(规则匹配置信度, 构件识别置信度)。
任一环节存疑 → 该行进复核队列，**不许按单一算式硬算**。

## 2. 标准可插拔：新项目来了怎么加

### 2.1 登记字段（缺一不可）

标准不是"列一堆名字"，是**一条可复核的登记记录**。新标准进场按下表登记，
登记不全的标准**不许用**（用了等于口径未声明）。

| 字段 | 填什么 | 缺了会怎样 |
|---|---|---|
| `standard` 标准名 | 全称 + 简称（如 `CESMM4`） | 规则无法被引用 |
| `version` 版本 | 版次 + **版本日期** | 旧版条文被当现行 → 与 §6 同类事故 |
| `scope` 适用范围 | 专业 / 地区 / 合同类型 | 房建规则套到道桥上 |
| `basis` 计量基础 | 净量 / 总量 / 展开 / 投影 / nominal，按分部逐条 | 槽位没对齐的假冲突 |
| `deduct` 扣减阈值 | 空洞/开口的面积与体积阈值 | 用标准默认值替项目值 |
| `unit_rounding` 单位与取整 | 单位制 + 各类量保留位数 | 同表两套量纲 |
| `mandatory` 强制条文 | **逐条列出**强制条款号（如 FIDIC Cl.12） | 把推荐做法当强制 |
| `priority` 优先级 | 落在 §4 链的哪一层 | 冲突时无法判定 |
| `source` 出处 | 条款号 / 图号 + 图面位置 / 合同条号 + `asof` | 出处不可定位 → 不算有出处 |
| `by` / `date` 登记人与日期 | 人 + 日期 | 无法追责，等同未登记 |

登记载体就是**敞口台账**的一行；`依据类型` 必须区分 **图读 / 规范推导 / 惯例**（见 `evidence-grading.md` §5）。

### 2.2 落地检查（开工前，逐条打勾）

```
□ 本项目用哪一套计量标准 —— 已确认（标准名 + 版本 + 版本日期）
□ 该项目有没有自己的计量前言 / Preambles —— 有则登记为第 2 层规则
□ 扣减阈值 —— 读自项目规则，不是套标准默认值
□ 单位制 —— 公制 / 英制已定；取整位数已定
□ 强制条文 —— 已逐条登记，未把推荐当强制
□ 每个计量对象都有已解析的 rule_id —— 未解析 → fail-closed（阻断，不猜）
```

**★ 阻断规则**：第 1 项（用哪一套 + 版本日期）未确认时，
在**建册的 Open Items 页登记为阻断敞口**，状态走 `DRAFT`
（见 `input-register.md` §3.3：存在 open 项即退出码 1，成果不得作为交付）。

"大概用 CESMM 吧"不算确认——**版本日期没定，条文就可能对不上**，
这与"基线不随表更新"（`gate_basis_freshness.py` 抓的那类）是同一个错法。

## 3. 各标准速查

> 用途是**认出这套规则属于哪一家、按什么基础计量**，不是背诵条文。
> 真用时按 §2.1 登记，并**回原文核条款**。

### 3.1 英联邦系（本项目国际标书最常见）

| 标准 | 适用 | 计量基础 | 单位 | 取整 | 备注 |
|---|---|---|---|---|---|
| **NRM2**（RICS） | 房建，英联邦/中东房建项目 | **净量**；空洞/凹口 < 0.5 m² / 0.5 m³ 不扣；钢筋不扣 | m/m2/m3/kg·t/nr | 2 位（m/m2/m3） | 分 计量工程 / 开办费 / 风险与暂列金；描述**自明**（项目特征写全），常不需另配单价表 |
| **CESMM4** | 土木与基础设施：**土石方、道路、排水、支挡、桥梁、管线、隧道、涉水** | 永久工程**净尺寸**；扣减按既定阈值 | m3（Class C/E）/ m2（Class D/F）/ kg（F）/ m·nr（G/H）/ t（I） | 2~3 位 | **A–Z 分类编码**：C 岩土土石方、D 道路、E 混凝土、F 混凝土附属（模板/钢筋）、G/H 管线、I 金属结构、K 桩与地连墙、Z **方法相关费用**（临时工程/机械/进出场，单独列） |
| **SMM7**（legacy） | 老项目、部分地区仍在用 | 同 NRM2 精神（砌体/装饰开口 ≤ 0.5 m² 不扣） | 同 NRM2 | 2 位 | 用 **Common Arrangement** 分部；项目指定 SMM7 时，规则按 SMM7、输出仍按 NRM2 式**完整描述** |
| **POMI**（RICS 国际版） | 国际/JV 项目，需"英国血统但中立"的计量基础 | 同 SMM7/NRM2；阈值通常 0.5 m² / 0.5 m³ | 公制为主 | 2 位 | **常配 Preambles**——前言里的计量注记就是项目规则，优先级仅次于合同 |

**CESMM4 的 Z 类（方法相关费用）是本项目最常被漏的一块**：
模板、支架、便道、降水、交通导改在道桥清单里不属于"永久工程净量"，
漏了不会在任何一道数值门禁里报错——只有开项清单能对（`road-bridge-openitems.md` X 分部）。

### 3.2 美标系

| 标准 | 适用 | 计量基础 | 单位 | 取整 | 备注 |
|---|---|---|---|---|---|
| **CSI MasterFormat** | 北美及美式国际项目 | 按**工作结果**分类：Div 03 混凝土 / 05 金属 / 08 门窗 / 22 给排水 / 23 暖通 / 26 电气 | 常用英制 | 项目定 | 用作**清单编码与描述**的组织方式 |
| **UniFormat** | 同上（元素级） | 按**元素**分类：A 下部结构 / B 外壳 / C 内装 / D 机电 | 常用英制 | 项目定 | 用于**元素级汇总与成本模型**，与 MasterFormat 是两套轴 |
| **AIA 约定** | 同上 | **由项目/合同定义**，非标准给定 | 常英制 | 项目定 | 扣减惯例**不统一** → 必读项目前言，**禁止把公制默认值直接搬过去** |

### 3.3 合同条件（不是计量标准，是"量怎么变成钱"的框架）

| 框架 | 要登记的点 |
|---|---|
| **FIDIC 红/黄/银皮书** | BOQ / 单价表：总价包干 vs 重新计量；**暂列金**（defined/undefined）与计日工；**变更 Cl.13**（变更量与原量分列、用同一套规则计量）；**计量与支付 Cl.12**（重新计量基础、取整、谁复核） |
| **合同专用条件 / 业主需求** | **压倒其下一切标准**（见 §4）；本项目阿尔及利亚 ANESRIF 与沙特 SPARK 两套合同的计量前言条款号必须逐条登记 |

### 3.4 本项目在用的设计与荷载规范（法标系 + 铁路荷载）

这些**不是计量标准**，但会通过**构造最小值**改变计量口径——登记进敞口台账，
并在受影响量行的 `依据类型` 标 **规范推导 + 推导链**：

| 规范 | 约束什么 | 对计量的实际影响 |
|---|---|---|
| **BAEL 91 Mod.99** | 钢筋混凝土（法系） | 保护层、锚固与搭接构造 → 影响含钢率推定与钢筋净量 |
| **BPEL** | 预应力混凝土（法系） | 预应力束构造与锚固区 → 影响钢绞线长度与锚具计列 |
| **RPOA 2008** | 阿尔及利亚抗震规范 | 抗震构造（含挡块、搭接长度）→ 影响钢筋量与抗震挡块是否单列 |
| **Fascicule 62 - Titre V** | 桥梁荷载与结构验算（法系） | 荷载组合决定截面尺寸；尺寸变了，量跟着变 |
| **EUROCODES**（EN 1990~1998） | 欧标体系 | 与法标并存时**先定用哪一套**（版本 + 国家附录），两套混用是口径错 |
| **UIC 71 + SW/0、SW/2** | 铁路荷载图式 | 铁路桥（如 VIADUC PK295+300）按 UIC71 加 SW/0（空载）或 SW/2（重载）→ 影响上部结构尺寸与配筋 |
| **地震 Zone 0** | 阿尔及利亚分区 | Zone 0 = 抗震构造要求最低档；**仍需确认该分区对应的构造条文是否要求设抗震挡块、最小嵌岩等**——构造要求改了，量就改了 |

**关键提醒**：设计规范给出的是**构造下限**，不是工程量。
把"最小嵌岩深度"读成"桩长下限"，就是下面 §6 那起事故。

## 4. 规则优先级链与冲突判定

### 4.1 优先级链（高 → 低）

```
1. 合同专用条件 / 业主需求（FIDIC Particular Conditions / Employer's Requirements）
2. 项目计量规则 / 工程量表前言（Preambles）/ 项目技术规范
3. 图纸设计说明与专用表（NOTES、支座表、BBS、DÉNOMINATION 构件表）
4. 选定的计量标准（NRM2 / CESMM4 / SMM7 / POMI / 项目自定）
5. 地区 / 行业 / 公司规则（含 §3.4 的规范构造规定）
6. 引擎默认行为
```

同一对象命中多条规则时：**优先级只决定"谁先被采信"，不决定"删掉另一条"。**

### 4.2 冲突判定动作（★源文件缺的就是这一段）

| 情形 | 动作 | 禁止 |
|---|---|---|
| 同一对象、两条规则**同优先级** | 标 `conflict`，**两条都留**，进复核队列 | 二选一 |
| 图纸说明与标准冲突 | 图纸说明优先，**但**合同明确排除的除外 → 仍标 `conflict` | 静默按标准算 |
| 两条规则的**数值阈值**不同 | 两个数**同时呈现**给复核人 | 自动择优、自动取中 |
| 变更单 / 澄清函 | 在其范围内**优先**；变更前与变更后**分列、可比** | 覆盖原量 |
| 规则未解析（无 `rule_id`） | **fail-closed**：阻断，不猜 | 用默认规则放行 |

### 4.3 冲突留痕字段（缺一不可）

冲突不是"记一笔就完事"，要能被人复算和追踪：

| 字段 | 内容 |
|---|---|
| `conflict_pair` 冲突双方 | 两条 `rule_id`（含各自所属标准 + 版本） |
| `source_a` / `source_b` 各自出处 | 条款号 / 图号 + 图面位置 / 合同条号 |
| `adopted` 暂取值 | 按 §4.1 采信的那一条 + 数值 |
| `rfi` RFI 编号 | 未编号即视为未挂账 |
| `by` / `date` | 登记人 + 日期 |
| `if_overturned` 若被推翻的处置 | 抄 `evidence-grading.md` §6 的写法，**不许写"待澄清"了事** |

**禁止**："已关注""持续跟踪"——那等于没有责任人（与质量体系的三态要求同源：
非 PASS 项必须是 已闭合 / 阻断 / 挂账 之一）。

## 5. 单位、换算与取整

引擎内部**一律用标准 SI**，仅在输出时换算。

| 量 | 公制 | 英制 | 换算 |
|---|---|---|---|
| 长度 | m | ft | 1 ft = 0.3048 m |
| 面积 | m2 | sq ft | 1 sq ft = 0.09290304 m2 |
| 体积 | m3 | cu yd | 1 cu yd = 0.764554857984 m3 |
| 质量 | kg / t | lb / short ton | 1 lb = 0.45359237 kg；1 short ton = 907.18474 kg |
| 管径 | DN (mm) | NPS (in) | **nominal，禁止算数互转**，查名义对照表 |

**取整**（缺省值，按项目覆盖）：
- 长度 2 位（m）；MEP 管线 3 位
- 面积 2 位（m2）；体积 2~3 位（m3）；质量 0~2 位（kg）或 3 位（t）
- **中间值永不取整**，只在出报表时舍入，全精度留在台账里
- 金额按项目定（通常 2 位），**只在行级舍入，不在计算中途舍入**

### 5.1 两条本项目专属规矩

1. **单位格式归一与量纲批准是两件事**。`M3（净量）` 剥离用途括注后可按 `M3` 识别；
   `CM（综合）` 剥离括注后仍然有歧义，不能全局认定为体积。只有项目单位别名注册表明确绑定
   当前项目、量纲、合同/标准来源条款、批准人和批准日期后，才允许按项目约定解释 `CM`。
2. **量纲归一后单价必须配套调整**，保持金额不变。归一是口径纠正，不是降价
   （实测只改量不改价，报价凭空掉 8% / 907 万）。

### 5.2 换算硬约束：禁静默换算（2026-10-24 增补，借鉴 pk-boq-db-match）

外部技能族的机制：单位换算必须**显式声明因子与来源**，机器只执行不验证。
落到本技能是三条规则：

1. **不同量纲之间不存在"换算"，只有"换算 + 一个物理假设"。**
   m³ ↔ t 要密度，m² ↔ m³ 要厚度，LM ↔ EA 要间距——
   这些假设必须写成人能核查的一行（`convert: {factor, note}`），
   **由人声明，AI 不代填**。
2. **静默换算是把量纲错洗成小数点错的标准动作。**
   表里记 CM、期望值按 SM 比，机器悄悄 ×0.1——差 10 倍看着像"小数点点错"，
   真正的量纲错误被藏了起来。所以单位不一致时**必须停下来**，
   不是"顺手除一下"。
3. **同名义不同进制不互转**（DN/NPS 的先例）：名义尺寸查表，不算术互转。

已落地的机器载体：

| 载体 | 行为 |
|---|---|
| `gate_expected_total.py` G-XST3 | 期望单位与匹配行单位不一致、且未声明 `convert` → **FAIL**（不是 WARN） |
| `gate_expected_total.py` G-XST5 | 声明了 `convert` → 打印因子与来源供审计；**门禁不验证因子本身对错** |
| `qto_vocab.validate_unit` | 单位不在词表 → 报"本行未做量纲校验"，不当成通过 |

一句话：**换算可以显式做，不能悄悄做。**

### 5.3 DN ↔ NPS 名义对照（示意，用时查表）

| DN (mm) | 15 | 20 | 25 | 32 | 40 | 50 | 65 | 80 | 100 | 150 | 200 | 250 | 300 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| NPS (in) | ½ | ¾ | 1 | 1¼ | 1½ | 2 | 2½ | 3 | 4 | 6 | 8 | 10 | 12 |

## 6. 抠原文的硬规矩（本项目真实事故）

**事故**：某条款写"基础深度在岩层中不小于软弱岩 1.5 m、完整岩 0.5 m"。
据中文**二手转述**判断"桩长 20 m 不满足"——**错了**。
该条约束的是**嵌岩深度**，不是桩长下限；桩长够不够取决于岩面标高，而岩面标高图上没有。

**规矩**：

1. 引用规范条款**抠原文**，不引二手转述。转述会把"某一段的深度"说成"总长"。
2. 引用时**必须区分约束对象**：约束的是总长、某一段深度、间距、还是根数？
3. 判据缺依据时，写 **"按规范推导 + 推导链"**，不写"待澄清"——
   除非澄清通道确实开着（通道关着写"待澄清"，等于把敞口藏起来）。
4. 推导链要能被人**复算**：每个数字标出处（图号 + 图面位置，或规范条款号 + 版本）。
5. 规范给的是**构造下限**，不是工程量。把下限当工程量，量的方向就错了。

**这也适用于标准本身**：NRM2/CESMM4 的阈值（0.5 m² / 0.5 m³）是**该标准的默认值**，
不是项目值。项目前言写了别的，按前言——这就是 §4.1 的第 2 层。
