# 主体—附属配对与系统完整性（防整组漏项）

> **在取量阶段（SKILL.md 第 2 步）逐构件过一遍**，量落表之前用，不是交付前补用。
> 本文每一条都有实测出处，不是通论。术语沿用 `road-bridge-reading.md`：口径、图证、红旗、推定、敞口。

> 一句话立场：**主体构件从来不是一个人来的，而被漏掉的那条尾巴，在算术上永远是自洽的。**
> 实测最狠的三处：某铁路桥只算主梁 3403.50 CM，横隔梁整项没进表（业主清单 6.36 = 3718 CM，差 315 CM 只能反算**推定**）；
> 支座垫石钢筋按含钢率 110 kg/m³ 推定 3.3 t，业主 6.27 = 11.1 t，差 **3.4 倍**；
> 某公路项目照明只算了灯杆，17 座箱变、43,566 m 接地导体、687 根接地极、526 座基础**整组没进清单**。
> 这类漏项**复算抓不到、门禁也抓不到** —— 算出来的数自洽得很。只能靠清单式扫描。

## 3. 表 B — 陪随构件 1:1 率自检

凡是"一个主体必然拖着另一个量"的，做比率断言。

| 主体 | 陪随 | 典型比率 | 实测案例 |
|---|---|---|---|
| 电力电缆（4C×N） | 接地导体 ECC（1C×n） | **1:1（等长）** | 照明图每回路 ECC 栏等长 → 43,566 m，整项漏 |
| 灯杆 | 灯杆基础 | 1:1 | 526 座高杆 → 526 个基础 |
| 灯杆 | 手孔井 | 1:1（按型式分） | TYPE2×526 + TYPE1×180 |
| 灯杆 | 接地极 | 1 : ~1.3 | 687 根 |
| 支座 | 支座垫石 | 1:1 | 30 m³ + 11.1 t，整项漏（§2.5 案例 2） |
| 主梁 | 横隔梁 | 按跨数 × 道数 | 315 CM，整项漏（§2.5 案例 1） |
| 桥台 | 前墙 / 梁座构造 | 1:1（逐台查） | ≈223 CM（§2.5 案例 3） |
| 桩 | 检测管 | 按桩径 | 常漏 |

**做法**（两条都要做）：

1. **相邻编排**：清单里陪随项紧挨着主体项，不允许中间隔别的分部 —— 隔开了人就不会对看。
2. **比率断言**：写一条可执行的断言，例如

   ```text
   Σ ECC 长度 == Σ 主缆长度 ±5%
   Σ 垫石数  == Σ 支座数
   Σ 基础数  == Σ 灯杆数
   ```

比率落在 **0**（漏计）或 **2 倍**（重计）都要进敞口台账，不许当成巧合放过。

## 4. 表 C — 系统树（机电自电源侧逐级核对）

**只从末端数起必漏上游。** 七层，每层都要在清单里找得到：

```text
① 上级电源   MV 中压电缆 / 上级变电站 / 引入路由（路由长度常无图注 → RFI，不填经验值）
    ↓
② 变电       箱式变电站 PS（含围栏、基础、接地、电缆沟）  ← 实测漏 17 座

③ 配电       配电盘柜（FP 馈线柜、照明配电盘、桥下照明盘）→ 进线 / 出线 / 备用回路
    ↓
④ 回路       电缆（4C×N）+ 接地导体 ECC + 保护管/导管 + 手孔井 + 敷设方式（直埋/穿管/桥架）
    ↓
⑤ 末端       灯具 / 设备 / 插座 / 电机（★一个符号可能代表 N 个计量对象：1 座 25m 高杆 = 6 套灯具）
    ↓
⑥ 配套       基础 / 支架 / 接地极 / 接地干线 / 防雷 / 标识
    ↓
⑦ 附属       桥下照明、隧道照明、利旧改造、既有拆除、调试
```

**实测教训**：某项目只计了第 ③ 层（FP 馈线柜），漏掉第 ② 层 17 座 PS 箱变与第 ⑥ 层全部接地系统 ——
因为清点时是从"灯"往回数的，数到配电盘就停了。**从末端往上游走一定会停在某个"看起来已经完整"的层。**

### 4.1 归组闭合（v4.6.0，机电必做）

系统图画得再全，不闭合就不知道有没有漏管、错接、漏数。**闭合只有一个等式**：

```text
Σ(各立管 × 各层接入器具数)  ==  Σ(平面图逐层点算器具数)
```

两侧不等时，**必居其三者之一**：漏管（系统图有、平面图找不到）、错接（接到别的立管）、
漏数（平面图数少了）。三者处置不同，所以必须**按立管逐管比**，不能只比总数——
总数相等而逐管不等，恰恰是最常见的错接（两根管互相串了器具）。

| 动作 | 内容 |
|---|---|
| **① 建基准** | 从系统图读：立管编号表（`JL/WL/FL/YL/TL` 或国际代号 `SW/SD/RW/V`）、各层接入器具数、分区、管径变化 |
| **② 实测** | 平面图逐层点数，**每个器具必须标所属立管编号**（这是归组键，不标就没法闭合） |
| **③ 闭合** | 按上表等式逐管比；另做"器具—点位"关联（1 洗脸盆 = 1 给水点 + 1 排水点，**口径须声明按器具还是按点位**，否则量差一倍） |
| **④ 五类不一致** | 漏项（系统图有、平面无）/ 孤项（平面有、系统无）/ 规格矛盾（管径、坡度）/ 数量不符 / 编号不符——五类分别记，不要合并成"有差异" |

**铁律**：系统图的管线交叉是**示意**，不能用于平面定位；**计数以平面图为准，系统图只作基准**。
反过来也不行——只按平面图计、不看系统图，会漏掉"平面图没画但系统图有"的那根立管。

## 5. 逐座设计差异 —— 同类构件不许套同一套参数

"同规格"不等于"同设计"。实测：同为 2500×1500 箱涵 ——

| 图号 | 壁厚（墙/板） | 总高闭合 |
|---|---|---|
| HA035062 | 墙 400 / 板 450 | 450+1500+450 = 2400 ✓ |
| HA035063 | 墙 350 / 板 400 | 400+1500+400 = 2300 ✓ |

**做法**：按填土高度/荷载逐座设计的项目，必须**逐座直读壁厚**，不许用统一 t=0.30 反算总量。
若已按统一值算过，**明细表与汇总表必然对不上** —— 这个矛盾就是"统一参数"的指纹，不是对账误差。

同理适用于（都在本技能里实测过）：

| 项 | 差异源 |
|---|---|
| 承台厚度 | 有盖梁体系 1600 vs 无盖梁柱式墩 1500（不是笔误） |
| 梁断面 | 桥1 0.90 m² 套到桥2 → 体系与断面都错 |
| 支座类型 | 盆式 vs 弹性板式（看 NOTE 的支座高度与厚度是否自洽） |
| 台身厚度 | 图上 0.45 是背墙局部厚，不是台身（实测楔形，修正 +622%） |

## 6. 图纸目录树反查分部

**图册的每个子目录都是一个潜在分部。** 建册时列目录树，逐个确认：

```text
DESSINS/
 ├ 01.GENERALITES/                  → 图号→图名对应（road-bridge-reading.md §0）
 ├ 02.OUVRAGES D'ART/
 │   ├ VIADUC PK295+300/            → 是否在清单？单幅/双幅口径是否声明？
 │   └ VIADUC PKxxx/                → 是否在合同范围？（不在也要登记 + RFI）
 ├ 03.BUSES/                        → 涵洞是否逐座开行？壁厚是否逐座直读？
 ├ 04.TERRASSEMENTS/                → 边坡率分区、软弱层
 ├ 05.CHAUSSEE/                     → 逐层宽度
 ├ 06.VOIE/                         → ★道砟归这里，别算进桥（§2.5 案例 4）
 └ 07.EQUIPEMENTS/
     ├ ECLAIRAGE/LAYOUTS/           → 布置
     ├ ECLAIRAGE/SOUS-OUVRAGE/      → ★桥下照明是独立分部（实测整分部漏）
     └ STANDARD DETAILS/            → 基础/接地/手孔做法，是量与做法的依据
```

**规则**：目录树里出现、清单里没有的 → 登记为待核项。
**不许默认"属于别的分部"或"不在范围内"** —— 范围问题要问，不能猜。

## 7. 使用方法

1. **开项阶段**：按 §2 四张子表逐主体建**模板编号**行（`A-2-3` / `B-3` / `C-5` / `E-2` …），**空的也要建**，标"本项不设"；同时在项目台账 `cbs_code` 列填本项目自己的编码（见 §8）。
2. **取量阶段**：每个主体过一遍表 A，逐条在备注写图证位置，或写"图纸未设"。
3. **桥梁专项**：额外过 §2.5 的六条 —— 横隔梁、支座垫石砼+钢筋、台身前墙、道砟归属、支座直读、高程链口径。
4. **出量后**：跑 §3 比率断言，比率为 0 或 2 倍的进敞口台账。
5. **机电分部**：按 §4 七层树**自电源侧向末端**走一遍，每层都要在清单里找得到行。
6. **建册时**：按 §6 列目录树，子目录数 vs 清单分部数对账。
7. **交付前**：把"未过项"汇总进审核发现清单，按 A 量级 / B 漏项 / C 量差 / D 规范 分级；每条写处置与责任人，禁止写"已关注"。

## 8. 编码映射与其他文件的衔接

### 8.1 模板编号 ↔ 项目 cbs_code（映射机制）

**两套编码同时存在，各有各的用处，不许互相替换**：

| 编码 | 谁用 | 性质 | 例子 |
|---|---|---|---|
| **模板编号** | `road-bridge-openitems.md`、`drafter_qto.py` 的 `CATALOGS["road-bridge"]`、本文 §2 四张子表 | **项目无关**，任何道桥项目通用 | `A-2-3`、`B-3`、`C-5`、`E-2` |
| **项目 cbs_code** | 台账 CSV 的 `cbs_code` 列、业主清单 | **项目特有**，随标段/业主体系变 | `CBS-OVA-I03`、`CBS-OVA-T04` |

`CBS-OVA-` 是 **PK295+300 这一个项目的前缀**（OVA 是该项目标段代码）。写进模板，沙特项目套不上，公路桥也套不上 —— **模板一旦带项目前缀就废了**。

**① 模板编号规则**：`{分部}-{层}-{序号}`

```text
A-2-3  →  桥梁(A) · 下部第2层 · 第3项
分部：A=桥梁 / B=涵洞 / C=道路路面 / E=机电 / X=其他
（road-bridge-openitems.md 中简写为 A2-3，与 A-2-3 同一编号）
```

**② 项目落地三步**：

1. 把模板编号**抄进台账**的 `template_id` 列（一条不落，包括"本项不设"的）；
2. 在 `cbs_code` 列填**本项目自己的编码**（业主清单码或我方 CBS 码）；
3. 两列**并排登记**，`drafter_qto.py coverage` 两边都认 —— 匹配模板编号或匹配项目码都算命中。

**③ 具体例子（PK295+300）**：

| 模板编号（通用） | 项 | 项目 cbs_code |
|---|---|---|
| `A-2-3` | 桥台台身 | `CBS-OVA-I03` |
| `A-3-1` | 支座 | `CBS-OVA-A01` |
| `A-3-2 / A-3-3` | 支座垫石砼 / 钢筋 | `CBS-OVA-A03 / A04` |
| `A-4-2` | 梁间横隔梁 | `CBS-OVA-T04` |

两侧序号**不必对应**（`A-2-3` → `I03` 只是本例恰好一致），映射以台账 `template_id ↔ cbs_code` 的实际登记为准。

**④ 反向复核（交付前必做）**：

```text
按模板编号逐条扫 → 哪些模板项在台账里没有对应行？
  有对应行            → 正常
  标了"本项不设"+原因  → 正常（原因必须可核查：图纸未设 / 不在合同范围）
  既无对应行也无说明   → 就是漏项，按 B 级（漏项）进审核发现清单
```

这一步的意义：**模板是全集，台账是子集，差集就是漏项**。靠项目 cbs_code 反查做不到这件事 —— 因为漏掉的行根本没有码。

### 8.2 文件与脚本衔接

| 文件 / 脚本 | 怎么用本文 |
|---|---|
| `road-bridge-openitems.md` | 开项清单按分部展开（A1 基础 / A2 下部 / A3 支座 / A4 上部 / A5-A6 桥面 / A7 附属 / B 涵洞 / C 路面），用的是**模板编号**。本文管"主体旁边还有什么"，那份管"每层要开哪些行"，两者互补，不重复。 |
| `drawing-reading-playbook.md` | T6 专用表直读（支座表禁止推算）、T5 尺寸链闭合（§2.5 高程链）、T4 矢量计数（桩/支座点数）是本文表 A 的取证手段。 |
| `road-bridge-reading.md` | §九"支座禁止按幅×跨×片×端推算"、§二"单幅还是全桥"是本文 §2.5 案例 5、6 的规则出处。 |
| `scripts/drafter_qto.py coverage` | 机器比对开项覆盖率：清单行 vs 目录 `road-bridge` 的配对项条数；`template_id` 与 `cbs_code` 两侧都能匹配。 |
| `scripts/gate_single_owner.py` | 抓反向风险：附属被开了两个入口（垫石既在桥台又在支座层各算一遍）。 |
| `scripts/gate_scope_declaration.py` | 本文每条配对项落表时都要带口径（单幅/全桥、单侧/两侧、每座/总计）。 |
| `scripts/xcheck_model_vs_2d.py --stage export` | 条目集合核对，抓"模型里有、二维表没导出"的整组漏。 |

**推定层的硬约束**（§2.5 案例 1、2 都落在这一层）：
推定只允许**把已实测量换算成已定价子目**，不得新增实物；
推定层单独分层、可整层剔除；每条推定必须能追到一个已实测量 + 一个图证缺口编号。
