# 三维模型 × 二维算量 交叉复核

> 模型的价值不是"看起来像"，而是**能独立算出量、和二维表互为印证**。
> 这一节讲怎么让这个印证真的成立。

## 一、两侧必须不同源（本机制的全部前提）

如果模型和二维表同抄一个错误参数（例如都按 0.65 m³/m 算梁），
比对结果会显示**完全一致 EXACT**，而实际上两边都错。

这是**共模错误**，是交叉校验能骗过自己的唯一方式。
**共模错误只有回原图重建参数才抓得到。**

所以每一条导出记录都必须写 `param_source`（参数来源）：

| param_source 写法 | 含义 |
|---|---|
| `HA-035061-001 图面直读` | 真·图读，可作基准 |
| `A13 经验值` | 经验推导，弱 |
| `沿用上一版` | **最危险**——共模错误的温床 |

`xcheck_model_vs_2d.py` 会检查：
- 两侧是否全部同名项数值完全一致 → 判**假通过**，直接 FAIL
- 是否有项未写 `param_source` → FAIL（没法判断是否同源）
- 某侧 `param_source` 只有一种 → WARN（大概率在同抄）

### 1.1 零差异告警（2.0.0 新增）——把"全一致"当可疑，不当好消息

**背景**：v1.x 只在文档里写了"两侧完全一致要警惕"，但脚本没有自动判据，
实际执行时"全 EXACT"被当成通过信号。本项目实测因此放过一次共模错误。

**判据**（任一命中即告警，不再默认"一致＝好"）：

| 码 | 级 | 条件 |
|---|---|---|
| **X0-ZERO** | WARN→FAIL | 参与比对的项中 **≥90% 相对差恰为 0.000%**，且两侧 `param_source` 出现同一出处词 |
| **X0-ONESRC** | FAIL | 任一侧的 `param_source` 去重后只剩 **1 种**出处 |
| **X0-NOSRC** | FAIL | 有项未写 `param_source` |

**处置**：命中的条目**必须让一侧回图纸重建参数后再比一次**，
并把重建后的差异（哪怕是 0.06% 这种小差异）记录下来——
**真实的两侧异源比对，几乎不可能完全一致**（如圆柱剖分会让桩/墩柱系统性低 0.06~0.11%）。

> 反过来说：**看到 0.06~0.11% 这种系统性小差异，反而是"两侧真的不同源"的证据**，
> 不要去"修平"它。

## 二、模型侧的量必须是"生成几何时登记"，不能事后补

模型的量必须在**创建几何的那个函数里登记**（例如建模时调`qrec(name, value, unit)`），
随构建过程累积导出。**事后照着二维表补登记，等于把二维抄了一遍，交叉校验立刻失效。**

导出格式（模型侧与二维侧统一）：
```json
[{"name": "箱涵混凝土", "value": 10127.73, "unit": "CM",
  "kind": "quantity", "param_source": "HA-035061-001 图面直读"}]
```

`kind` 取值：
- `quantity`：模型有独立几何，可比
- `lot`：定额项，模型无独立几何，**不可比**，需 `--skip-lot`排除

## 三、可比范围必须先声明（硬规矩）

不是所有量都能比。钢筋、模板、支座这类 LOT 在模型里通常没有独立几何，
硬比会得到一堆假 MAJOR——**比不比对更糟**，因为它会让人对整套机制失去信任。

**排除范围必须写进交付说明**，不能让读者以为全专业都验过。
未参与交叉复核的项**只经过单一来源核算，不具备双源印证**。

## 四、两阶段：先抓导出，再比数值

**第一阶段（`--stage export`）核对条目集合**。
实测首轮出现的"差异"，全部是导出问题而非算错：
- 可选项标记漏写 → 该项被误剔
- 远期口径误剔 → 桩号范围外的项被删
- 构件漏登记 → 模型建了但没报量

**所以第一次看到差异，先怀疑导出，再怀疑被检对象。**
但确认导出无误后，必须回到图纸查真实原因——不能停在"可能是导出问题"。

**第二阶段（`--stage value`）比数值**，三档判定：
| 档 | 阈值 | 处理 |
|---|---|---|
| EXACT | ≤0.5% | 一致 |
| MINOR | ≤5% | 需在交付说明写清原因 |
| MAJOR | >5% | **必须处置，不许用"大致相当"放过** |

## 五、模型定位：独立复核器，不是全项目量源

模型在体系里的正确位置：

- ✅ **是**二维算量的独立复核器——两条路各走一遍，互为印证
- ❌ **不是**全项目量源——钢筋/模板/支座等LOT 模型覆盖不了

反过来也一样：二维表不是"抄模型"就对了。
两侧各有各的价值：**模型能提前暴露几何冲突**（构件打架、结构自相矛盾），
**二维表能表达模型表达不了的东西**（计量规则、计价口径、分部分项）。

## 六、收尾必做：抽查参数是否真的来自图纸

每一轮交叉复核之后，抽若干关键参数，确认它是**真的来自图纸**，不是来自上一版脚本。

这个动作看起来多余，但它专门抓共模错误——
上一轮把参数抄进这一轮，两侧就"一致"了，只有回到图纸才能发现。

## 七、常见失败与处置

| 现象 | 先查 | 再查 |
|---|---|---|
| 全一致 | **同源**（假通过） | — |
| 某项差很大 | 导出（标记/口径/单位） | 参数是否沿用上一版 |
| 某项只在一侧有 | 漏登记 / 漏建模 | 是否本就不该在模型里 |
| 两次复核结果一样 | 参数被固化了 | 抽回图纸核 |

## 八、命令

```bash
# 环境先查
python scripts/check_environment.py

# 第一步：条目集合（抓导出漏项）
python scripts/xcheck_model_vs_2d.py model.json t2d.json --stage export

# 第二步：数值比对，排除不可比 LOT
python scripts/xcheck_model_vs_2d.py model.json t2d.json --stage all --skip-lot 钢筋 模板 支座

# 出报告（自动列出未纳入比对的项= 覆盖边界）
python scripts/xcheck_model_vs_2d.py model.json t2d.json --skip-lot 钢筋 模板 支座 \
        --report 交叉复核报告.md
```

退出码：有 MAJOR / 疑似同源 / 条目集不一致 → 1。

## 九、断面读法图内四重复核（不把复核推给人 · v4.5.3 新增）

实测痛点：AI 反复把"断面尺寸是否读对"推回人工"回图复核"，违反不打断协议（第 L91-93）。
断面能否读对，**完全可以只靠图面自身信息在图内闭环验证**，无需离开当前图、无需人工。

以 Ras El Hekma SB-01 主断面（000452）为例，五重图内印证全部闭合才落数：
1. **比例尺校验**：图面标尺 11.34 pt/m vs 标题栏 1:250 理论 11.3379 pt/m（差 0.02%）→ 比例可信。
2. **尺寸链闭合**：顶宽 20.2 = 2×5.5(护面) + 2×2.1(垫层) + 5.0(芯) → 竖向层厚栈自洽。
3. **图例互证**：图例文字 'Concrete Armour Units (16m3)' / 'Underlayer 2-4 ton' 与层厚一致。
4. **侧向投影复核**：床 −14 时基准宽 = 20.2 + 2×1.5×14.16 = 62.7 m ≈ 平面实测 61.7 m（差 1.6%）→ 边坡 1.5:1 可信。
5. **体量反算**：护面体积 ÷16 = 15,765 件 vs 业主 BOQ 15,915（差 −0.9%）→ 护面体量验真。

**机制要点**：
- 这五条**都在同一张图内**，不依赖任何外部图或人工。
- 尺寸链若出现歧义（如某段标注到底套哪条尺寸），**用上面任一条独立复核消解**，不要靠假设落数；
  任一条明显偏离（尺寸链加总 ≠ 标称顶宽、或侧向投影差 >5%）→ **先停、回该图重读**，不要落数。
- 体量反算命中 BOQ 只是"护面体量验真"，**不代表内部分层唯一确定**
  （如 SB-01 芯/垫层在单主断面下无法唯一分，属已知敞口，需如实标注，不影响护面体量）。
- 判定为"图内已闭环"后，**交付说明里写明五重校验已自行完成**，不再写"需人工回图复核"——
  那是把机器该做的工作甩给人，直接违反不打断协议。
