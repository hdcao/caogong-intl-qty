# 数量口径与分层（v4.0.0）

> 适用：所有专业、所有合同类型。目的是让每个数字都能回答三个问题：**这是什么量、怎么算出来的、能不能交**。

---

## 1. 六层数量：不得混写

| 层 | 含义 | 从哪来 | 能不能直接进 BOQ |
|---|---|---|---|
| `design_theoretical` 设计理论量 | 图纸/模型直接几何量 | 矢量算量、几何聚类 | 不能 |
| `contract_measured` 合同计量量 | 按指定测量规则扣减/分类后的工程量 | 设计理论量 + 合同规则 | **能**（这是投标量） |
| `material_requirement` 材料需求量 | 加损耗后的需求量 | 计量量 + 经批准的损耗参数 | 不能（另表） |
| `procurement` 采购量 | 按包装/供货规格取整 | 材料需求量 + 供货约束 | 不能（另表） |
| `tender_boq` 投标/BOQ 数量 | 按合同清单口径汇总 | 合同计量量 → BOQ 编码映射 | **能**（报价用） |
| `certified_payment` 申报/认证量 | 本期申报、经工程师认证的已完量 | 合同计量量 ∩ 本期已完范围（扣保留项、扣未闭合 OI） | 不能（付款用） |

**第六层是 v4.6.1 补的**：`SKILL.md` 一直写的是"六项必须分开"，而本文此前只有五层——
少的那一层正是结算争议的起点。"合同计量量"直接当"本期申报量"，会混掉三件事：
计量周期（monthly statement）、已计量未认证、已认证未支付。**保留项（retention）与
未闭合 OI 扣不扣，必须写死**，否则每期付款都要重谈一次。

铁律：

1. **墙面几何面积不得因为有涂料损耗就改写成更大的计量面积。** 损耗只在材料需求层出现。
2. 损耗率、供货取整规则必须有项目批准出处；没有出处就不许出材料需求量。
3. **钢筋的三件事必须分开记，混一次就是几十吨**：弯钩是**图示几何，必计**；
   搭接是**施工措施，默认不计**（仅当前言明文 `laps measured` / `extra over for laps` 时计，
   且须引用条款原文）；损耗是**定尺余料与切断损失，任何规则下都不进 `contract_measured`**。
   把搭接归进"损耗"这一类，会让人以为损耗也可以"选着计"——损耗没有选项。
3. 任何一层的数字都不得被当成另一层使用（"计量量当采购量报"是常见高发错误）。
4. 测量标准（NRM / CESMM / ARM / 项目专用规则）与工程分类（CSI / OmniClass / 项目 CBS）与
   成本报告口径（ICMS）**三者是三件事**，不得互相替代。

## 2. 识图口径三防（v4.0.0 新增，来自实测教训）

这三条不是"注意事项"，是**会整批虚报**的错误，必须在工具层拦住。

### 防1 图例页 / 符号示意页 ≠ 安装量

图例页、符号示意页、系统样例页上布满符号（灯、风机、喷头、阀门…）。
这些符号的用途是**说明型号与符号的对应关系**，不是"这里有一台设备"。

- ❌ 错：把符号页上的 540 个 X-UNIT 图元计成 540 台设备。
- ✅ 对：图例页**不产出任何安装量**；改为读出"有几种型号、每种符号长什么样"，
  产出「符号↔型号对照表」单列存档；真正的安装量在布置图上点算。

判定依据（任一命中即判图例页）：
- 图号/文件名/标题含 `LEGEND` / `SYMBOL` / `KEY` / 图例 / 符号 / 示意 / 缩写表 / 索引表；
- 图元全部落在图例专用图层（`X-UNIT-*`、`HC-L-S&S-W-SYMBOLS`、`HC-FP-SYMBOL`、`HC-DOCKET`、
  `00 - L7` / `00 - L36`）且该图无布置类图层；
- 文本内容是管径/规格（⌀25/⌀50）而非"编号+位置"。

工具：`scripts/qto_legend_guard.py classify`

### 防2 标签块 / 文字标注块 ≠ 构件

`DOOR TAG`、`WINDOW TAG`、`ANNO-TEXT-TAG` 这类块是**给构件贴的标签**，不是构件本体。
按块实例计数 = 把一扇门数成十几樘。

- ❌ 错：门标签块 19369 个 → 报 19369 樘门。
- ✅ 对：门本体块 1879 樘；标签块单独留痕用于回证型号。

判定依据：块名/图层名命中 `DOOR TAG` / `WINDOW TAG` / `ANNO-TEXT` / `ID-TAG` / `NAME-TAG` 等。

工具：`scripts/qto_legend_guard.py classify`

### 防3 同代复本 ≠ 多份图纸

同一张图被转存成多个文件名（图号族：一张图拆成 A/B/C/D 四个图号），
内容指纹相同。按文件数计量 = 4 倍虚报。

- 内容指纹算法：`实体类型 | 图层 | 块名/文本` 排序后取 MD5，忽略文件名与路径。
- 判定：同 `sig` 即同内容，只取 1 张计量。
- **例外**：确属不同版本（内容确有差异）→ 用文件内部版本时间（DXF header `$TDUPDATE`）
  裁决，按"版本时间较晚者为准"，并把裁决写进 OI 台账。

工具：`scripts/qto_legend_guard.py dupes`

## 3. 体系乘数（全局最大不确定性）

重复区段/多塔楼/多栋的乘数一旦错，整份 BOQ 等比例错。

- 乘数必须**登记在测量策略卡** `system_multiplier.declared`，并写明图证。
- 典型区先量一次 → 按实例数展开 → **与典型层的差异单列**，不做整组套用。
- 乘数来源不明 → 状态 `待确认`，量**不进**交付总量，转敞口台账。

工具：`scripts/qto_repeat_groups.py expand`

## 4. 什么情况下必须"拒绝出数"

以下情形不许给貌似精确的数字，只能给敞口/RFI：

1. 比例尺未双校准，或图纸比例与标注尺寸矛盾；
2. 缺少计算所需的尺寸；
3. 结构边界不闭合，或识图结果存在多个合理解释；
4. 相邻房间交界线不能证明就是门洞位置；
5. 设备符号可能重复计数（含图例页干扰）；
6. 设计图与设备表/规格书冲突；
7. 无法判断某项工作属承包商还是业主供货范围；
8. 乘数/版本冲突未裁决。

**正确拒绝率**是算量系统的质量指标之一：能在上述情形下正确停下，
比多算 3% 的量更有价值。

## 5. 落账时数量分层怎么填

台账一行只记**一个**层的量，层写在 `note` 或单独的 `quantity_layer` 列：

```
reading_id, ..., value=1879, unit=樘, note="层=contract_measured；口径=门本体块计数（DOOR TAG 标签块不计）"
reading_id, ..., value=19369, unit=樘, note="层=label_only；DOOR TAG 标签块计数，仅作型号回证，不进 BOQ"
```

同一条读数不许同时表示两层。
