# 质量体系：十维 × 十一岗 双轴

> 本文件回答一个问题：**凭什么相信这份算量是对的？**
> 答案是"每个专业只回答它能看见的那一部分，并且对看不见的部分明确说不负责"。

> **v2.0.0 修订提示**：本版对 v1.x 的三处设计做了专家视角修正，见 §11。
> 修正要点：否决权从"每岗一条"改为 **RACI 唯一 accountable**；
> 置信度从"加权百分数"改为 **覆盖度 + 证据构成**；
> 证据从"单一档位"拆为 **数量证据 + 价格成熟度** 两个维度。

---

## 一、为什么要两轴

只有专业维度（十维）会出现一种致命情形：
**每个专业都说自己那块没问题，却没有一个人愿意为整体签字。**

所以在其后加一层岗位维度（十一岗）：

| | 十维 D1~D10 | 十一岗 PG-01~PG-11 |
|---|---|---|
| 组织方式 | 专业分工 | 岗位角色 |
| 回答 | 这块内容有没有人看 | 这个位置有没有人担 |
| 产物 | 专业结论 | 审阅意见 + 闭合状态 + 置信指标 |
| 失效方式 | 某一专业整块漏掉 | 全都看了，但没人愿意为它负责 |
| 谁签发 | 各维 accountable（人） | AI 出意见，人追认或推翻 |

两者**正交不替代**。同一笔土方成本：造价看算得对不对，施工看挖得出来吗，
项目经理看敢不敢承诺，合同经理看出事能不能索赔——
四个答案可以**完全不同且都成立**。

## 二、十维总表（看什么）

每维只能回答一个问题，不越界。

| 维 | 名称 | 唯一视角 |
|:--:|---|---|
| **D1** | 范围与合同边界 | 算的东西是不是合同要求的 |
| **D2** | 工程量与图纸依据 | 每个数能不能指到一张图 |
| **D3** | 指标对标与量级合理性 | 这些数放在世界上荒不荒谬 |
| **D4** | 成本结构与组价口径 | 三层口径有没有串味 |
| **D5** | 风险与应急 | 未知风险有没有留钱 |
| **D6** | 商务与税务 | 税负按合同落位、代收代付不加成 |
| **D7** | 工期与施工方案 | 报价对应的工期可不可实施 |
| **D8** | 报价策略与合规 | 策略在不在业主硬约束内 |
| **D9** | 编码与可追溯 | 每条数据有没有唯一身份 |
| **D10** | 数据完整性与防脱钩 | 三份产物是不是同源 |

**D2 是算量工作的主战场**，也是本技能投入最多门禁的一维。

## 三、十一岗总表（谁有权拦）

每岗除了"能看什么"，还必须写清**明确不看什么（→交给谁）**——
这条是关闭责任真空的关键。

| 岗 | 名称 | 只能看什么 | 明确不看（→谁） |
|:--:|---|---|---|
| PG-01 | 总工程师 | 技术方案可行性、设计责任边界、技术假定对量的影响 | 单价来源、税务、付款机制（→04/08） |
| PG-02 | 施工经理 | 可施工性、资源与工效、临时工程、施工组织约束 | 单价构成、合同条款、模型精度（→04/08/07） |
| PG-03 | 项目经理 | 整体交付承诺、组织与管控、里程碑与付款匹配 | 单项单价、图纸细节（→06/01） |
| PG-04 | 合同经理 | 合同条件、付款机制、索赔路径、保留权利、税负落位 | 工程量算法、施工工效（→01/02） |
| PG-05 | 资深 QS | 资格预审要求对报价结构的约束、计量规则符合性 | 施工工艺、单价合理性（→02/06） |
| PG-06 | 资深成本专家 | 单方造价、分部占比、与同类项目的可比性与分位 | 图纸细节、合同条款（→01/04） |
| PG-07 | BIM 专家 | 模型与图纸/工程量表的一致性、模型边界、模型交付要求 | 单价、商务条款（→06/04） |
| PG-08 | 采购经理 | 单价来源与询价覆盖、供应商锁定、长周期设备、价格时效 | 工程量算法、税务（→01/04） |
| PG-09 | 计划经理 | 工期与资源曲线、关键线路、降效系数、S 曲线与付款匹配 | 单价、合同条款（→06/04） |
| PG-10 | QA/QC 经理 | 质量体系本身是否被执行：自检、NCR 闭环、检查完成率 | **全部专业判断**（只管"查没查"，不管"对不对"） |
| **PG-11** | **绘图员 / 建模算量岗** | **图元与标注的对应关系、读数落账、构件几何与落位** | 单价、合同条款、税务（→04/06/08） |

### PG-11 的否决条件（有且只有一条）

> **任何一条进入合计的读数，若绘图员无法当场指到图面上的具体位置，PG-11 有权拦下整行。**

这一条其他任何岗都管不了——“这个数在图上哪儿”只有绘图员能答。
详见 `references/drafter-qto-role.md`。

## 四、责任矩阵（RACI）—— 替代"每岗一条否决权"

### 4.1 为什么改

v1.x 规定"每岗有且只有一条自己的否决条件"，理由是
"如果每个问题任何岗位都能拦，签字就失去意义"。

**这个理由成立，但推论错了。** 真正的问题是：
**谁对这件事负最终责任（accountable）**——而不是"谁能拦"。

现实中：

| 失效 | 表现 |
|---|---|
| 人人都能拦 | 无人敢签，或互相等对方先签 |
| 每岗挂一条形式化否决条件 | 与实际签字链脱节，成了表格装饰 |
| APS 阶段"未审" | 悬空态，既不说看也不说不看的理由 |

### 4.2 新规则

**每个维度（D1~D10）在每一轮里，必须且只能指定一个 accountable（A）。**

| 标记 | 含义 |
|:--:|---|
| **R** Responsible | 编制 / 计算 / 落账的人（可以有多个） |
| **A** Accountable | **唯一**，对该维度签字放行、有否决权 |
| **C** Consulted | 需被咨询的专业岗 |
| **I** Informed | 需被知会 |
| **N** Not applicable | 本轮不适用，**必须写明原因** |

**关键约束**：

1. **A 唯一**——一个维度只能有一个 A
2. **R ≠ A**——编制人和批准人不能是同一个（自审自批无效）
3. **N 要写原因**——不留悬空的"未审"
4. **A 未定时，该维度视为未闭合，不得进入交付**

### 4.3 默认 A 分配（可按项目调整，但必须显式写出）

| 维 | 默认 accountable | 默认 responsible |
|:--:|---|---|
| D1 范围与合同边界 | PG-04 合同经理 | PG-03 项目经理 |
| D2 工程量与图纸依据 | **PG-11 绘图员** | PG-05 资深 QS |
| D3 指标对标 | PG-06 成本专家 | PG-05 / PG-11 |
| D4 成本结构与组价 | PG-06 成本专家 | PG-05 资深 QS |
| D5 风险与应急 | PG-03 项目经理 | PG-04 合同经理 |
| D6 商务与税务 | PG-04 合同经理 | PG-08 采购经理 |
| D7 工期与施工方案 | PG-09 计划经理 | PG-02 施工经理 |
| D8 报价策略与合规 | PG-03 项目经理 | PG-04 合同经理 |
| D9 编码与可追溯 | PG-05 资深 QS | PG-11 绘图员 |
| D10 数据完整性与防脱钩 | PG-10 QA/QC | PG-07 BIM 专家 |

> **D2 的 A 是 PG-11 绘图员**——这是"绘图员负责算量"在签字链上的落点。
> 算量工程师（PG-05）负责计量规则与方法，但**读数是否正确由绘图员负责**。

## 五、签发边界：AI 不代签

| AI 可以做 | AI 不可以做 |
|---|---|
| 跑机判项、汇总会签单、汇总 NCR | 代答人判项 |
| 提示"这条你没答" | 判断"这条不用答" |
| 生成证据位置索引（文件/页码/单元格） | 声称"我已核查并确认无误" |
| 在 FAIL 时阻断流程 | 在 FAIL 时"综合判断后放行" |

**脚本层硬约束**：签发栏一律输出 `＿＿＿＿＿＿`，代码里不写入任何姓名。

这不是疏忽，是设计——
**只要有一行代码能写名字，就总有一天会有人让它写。**

## 六、抽检：验收工具自身也要被验收

**抽检不是"再跑一遍原函数"**，而是换一条独立代码路径重算：

| 审阅项 | 原实现 | 抽检实现 |
|---|---|---|
| 钢筋是否齐全 | 按编码前缀匹配 | 直接列举全部含关键字的行，逐行看 |
| 表项数 | 读一张表 | 两张表分别统计再比对 |
| 总价 | 取该行 ≥1e8 数值的 min/max | 读表头定位列位直取 |
| 支座数 | 清单值 | **几何推导**（13 跨 × 2 端 × 10 片 = 260） |

**反向抽检**：另抽几项 PASS 结论做反例检索，确认不是"假通过"。

**抽检器自己也会写错。** 本项目实测被抓过：

| # | 抽检器自身的错 | 后果 |
|---|---|---|
| 1 | 按错列名找表 | 统计数虚高 |
| 2 | 按关键词蹭到表头说明行 | 误判为数据行 |
| 3 | 把"缺陷必然成立"写死成判据 | 永不报错的假防线 |
| 4 | 支座期望值硬编码 234（应为 260） | 修订后误报 |
| 5 | 锚点格 E21 随增行漂移 | 跨表核对失效 |

**抽检器写错同样要被抓住，否则它只是多一道仪式。**

本技能的对应实践：`scripts/gate_fault_injection.py` 往表里注入已知缺陷，
看门禁抓不抓得到。**捕获率不达 100% 不算这套门禁上线。**

## 七、独立信号：换脑子才算第二只眼（2026-10-24 增补）

§六 说"验收工具自身也要被验收"。这一节补另一半：**出结论的人，不能是审结论的人。**

### 7.1 铁律一：同一模型的自校验不算独立信号

外部技能族（pk-boq-ai-team）的实测教训，原样照抄价值：

> Matcher 与 Auditor 曾同用 Sonnet，**误配在校验层同样通过**。
> 同一个脑子复核自己，拦不住自己。

他们的处置是把设计 / 执行 / 审核 / 决策四个角色**固定绑不同模型**。
本技能不需要四模型流水线（那是报价链的规模），但结论一致：

- **本技能的七岗评审能抓到东西，前提是七个上下文互相看不到结论。**
- 反过来，2026-10-24 对比的 openclaude 单遍算量，其自校验第 6 条
  自己写明"非独立验证，受 A1 支配"——**它知道，但没有任何机制逼它换脑子。**

### 7.2 铁律二：填报与审核必须分开上下文

pk-boq-quotation 的原话值得逐字记：

> 一个人干完全程时看不见自己的错——刚决定"这字段读不到就留空"的推理链，
> 回头审会用**同样的理由**认定留空合理。

落到本技能的三条动作：

| 动作 | 要求 |
|---|---|
| 填表与审表分轮 | 读数四问填表（`drafter_qto.py add`）与挑错不在同一轮对话里完成 |
| 审阅者握源文 | 审阅必须能翻开**图册与业主清单原文**；只拿中间产物（汇总表 / manifest）的审核，结构上发现不了遗漏 |
| 审阅留痕 | 审阅结论走 `human-review-loop.md` 的变更表，不落在对话里 |

### 7.3 铁律三：汇总只算一次，且必须有期望总额闸门

pk-boq-compare 的两条：匹配结果只算一次；`--expect-total` 传期望总额，
差额在容差内才写盘。

本技能对应物：**G-XST**（`gate_expected_total.py`）。
本项目实测：业主 BOQ 五项反算 5/5 闭环（3718 vs 3718.5，差 +0.01%）。
**没有期望值时，"全部门禁通过"不说明任何事**——这正是 v2.1.0 之前
"13/13 全绿"而 G-UNIT 检了 0 行、G-PROP 算了 0.00 元的原因。

### 7.4 铁律四：源侧从源列直读，禁止"同错对消"

pk-boq-merge 的教训：列映射一出错，源侧与输出侧**同错对消**，
验证假通过——"Quantity 错位"那个 bug 就是这么藏住的。

本技能对应物：`colmap` 列映射冲突即拒跑（exit 2）、G-EXIT 把 exit 2
从"通过"里剔出去。同类变体：**只核工程量不核金额等于完全不核**
（0.00 vs 0.00 恒 PASS）——APS 无单价表上，G-UNIT / G-PROP 判"未运行"
而不是"通过"，就是这条铁律的落地。

### 7.5 每轮交付前问一句

> **这一轮里，有没有任何一个结论，是由得出它的人确认的？**

有 → 那一项不计入"已核"，按挂账处理。这条问题不需要工具，
但它能在 10 秒内揭穿大多数"全绿"。

## 八、闭合规则：闭合不等于消除

每条非 PASS 必须有去向，三态之一：

| 状态 | 含义 | 要求 |
|---|---|---|
| **已闭合** | 本轮实际修掉并复验通过 | 须有复验证据（重跑后该项转 PASS） |
| **阻断** | 必须处置才能进下一步 | 须指明外部依赖（谁提供、何时提供） |
| **挂账** | 有结论、有责任人、有时限 | 须写清"什么时候、做到什么程度" |

**禁止**在报告里写"已关注""持续跟踪""下阶段落实"——这些等于没有责任人。

## 九、置信指标：不做主观打分（v2 修订）

### 8.1 为什么改

v1.x 用「权重 × 实测通过率」加权出一个百分数（如 **94.0%**）。
问题：**权重本身是主观的**，两位小数看起来精确，实则不可复算。

### 8.2 新指标：两个数，都客观可数

| 指标 | 算法 | 说明 |
|---|---|---|
| **覆盖度** | 机器验过的基准条数 ÷ 基准总条数 | 分母是真实的条目总数，不是拍脑袋的权重 |
| **证据构成** | 图纸确认 / 推算 / 估算 / 待核 各多少条 | 直接看证据结构，不折算 |

**报告写法**：
```
覆盖度 34/34 = 100%
证据构成：图纸确认 14｜推算 16｜估算 4｜待核 1
```

> 不给"94.0%"这种数字。**可数就说数，说不清就承认说不清。**

### 8.3 置信的边界

**模型置信度不覆盖报价可信度。**
模型几何再准，也不能说成本可靠——
**回价没拿到之前禁止称同等置信度。**

## 十、门禁分级（v2 新增）

v1.x 把 8~9 道门禁平铺，每次全跑。问题是**门禁越多越没人看**。
现按触发时机分三级：

| 级 | 何时跑 | 门禁 |
|---|---|---|
| **核心** | 每次计算后必跑 | G-FRESH（基准时效）→ G-E（量 vs 基准）→ G-SUB（多小计逐组） |
| **交付** | 出交付物前跑 | G-OWN（一物一入口）｜G-A（口径声明）｜G-B（单/全成对）｜G-UNIT（单位量纲）｜G-DW（跨列自洽）｜G-XS（跨表一致）｜G-XSC（映射覆盖率）｜G-X0（不同源）｜**G-XST（期望总额闭环）** |
| **专项** | 特定情形 | G-PROP（OPTIONS 分离）｜G-FI（故障注入，上线前/判据变更后）｜`boq_lint`（审任意既有清单） |

**顺序要求（不能反）**：

```
核心门禁里：先 G-FRESH（基线可不可信），再 G-E（拿可信基线比数值）
              —— 基线过期时，"数值全部相符"是假通过
```

## 十一、v2.0.0 专家视角修正清单

| # | v1.x 设计 | 问题 | v2.0.0 修正 |
|---|---|---|---|
| 1 | 每岗"有且只有一条否决条件" | 形式主义；与实际签字链脱节 | 改为 **RACI 唯一 accountable**，A 未定即未闭合 |

| 7 | 8~9 道门禁平铺全跑 | 门禁越多越没人看 | 分**核心 / 交付 / 专项**三级 |
| 8 | "不适用 DWG/DXF" | 国际工程大量 DWG 原生；限制不合理 | **格式无关**：DWG/DXF/PDF/扫描各有取证路线 |
| 9 | 无跨列一致性门禁 | A02 单位 SM vs 口径 m³ 逃过所有门禁 | 新增 **G-DW**（`gate_dimension_wording.py`） |
| 10 | 无分部缺失检测 | 图纸目录里有子目录但清单里没有 | 新增 **开项清单比对**（`drafter_qto.py coverage` + `road-bridge-openitems.md`） |
| 11 | 停止条件 4 条 | 缺"体系判不出""只能靠经验值""整子分部未确认范围" | 补至 7 条 |
| 12 | 无"绘图员负责算量"机制 | 读数错误的责任人不明确 | 新增 **PG-11 + 读数台账 + 读数四问**（`drafter-qto-role.md`） |
