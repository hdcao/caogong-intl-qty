# 跨图一致性校验（Cross-Drawing Consistency）

> **这份文件补的是一个真空。** 现有三道门禁分别管：一张图内尺寸链闭合（`chain_check` / G-CHAIN）、
> 一个工作簿跨页签汇总一致（`gate_cross_sheet` / G-XS）、模型与二维互校（`xcheck_model_vs_2d` / G-X0）。
> **"图纸 A 与图纸 B 对同一参数说了两个数"这件事，此前没有人管。**
>
> 而它是算量返工的最大来源之一：层高在说明里写 3600、在剖面里写 3300，你按哪个算？
> 算完才发现，等于整层重算。国际项目更严重——法语图册的 `PLAN / COUPE / ÉLÉVATION / NOTICE`
> 常分属不同 rev，且图名与图种时常对不上（见 `drawing-reading-playbook.md` §0.2）。

---

## 一、校验矩阵（4 组 22 项）

矩阵不是穷举清单，是**默认要过一遍的最小集**。项目可增项，但删项必须写明理由
（"本项目无立面图"是合法理由；"时间紧"不是）。

### A 组 · 平面 × 立面（5 项）

| # | 校验参数 | 平面侧取什么 | 立面侧取什么 | 典型错法 |
|---|---|---|---|---|
| A1 | 外窗水平位置 | 窗中心到最近轴线距离 | 同一窗到同一轴线距离 | 立面按均分画，平面按实际开间 |
| A2 | 外窗宽度 | 洞口宽标注 | 立面窗宽标注 | 立面画的是立面投影，含窗套 |
| A3 | 外门位置与宽度 | 门洞定位 | 门在立面的位置 | 门厅大门常只在一侧有标注 |
| A4 | 阳台 / 雨篷出挑 | 平面挑出深度 | 立面挑出深度 | 平面画到栏板外皮，立面画到结构边 |
| A5 | 外墙材料与分格 | 平面外墙索引 | 立面材料标注 | 平面只写"见立面"，等于没有值 |

### B 组 · 平面 × 剖面（6 项 · **最容易出大事**）

| # | 校验参数 | 平面侧取什么 | 剖面侧取什么 | 后果 |
|---|---|---|---|---|
| B1 | **层高** | 楼层标高差 | 剖面层高标注 | 整层体积、模板、砌体全错 |
| B2 | 门洞高 | 门窗表门高 | 剖面门洞高 | 门、过梁、砌体开口 |
| B3 | 窗台高 | 门窗表窗台高 | 剖面窗台高 | 窗侧砌体、外墙面砖 |
| B4 | **楼梯净高** | 楼梯平面梯段长 | 剖面梯段与净高 | 楼梯混凝土量与净高合规 |
| B5 | 室内外高差 | 首层标高 ±0.000 与室外标高 | 剖面室外地坪 | 土方、台阶、外墙高度 |
| B6 | 吊顶净高 | 平面吊顶标高 | 剖面吊顶 | 吊顶面积、机电净空 |

### C 组 · 立面 × 剖面（5 项）

| # | 校验参数 | 立面侧取什么 | 剖面侧取什么 | 后果 |
|---|---|---|---|---|
| C1 | **建筑总高** | 立面最高点标高 | 剖面最高点标高 | 外立面面积、脚手架、垂直运输 |
| C2 | 逐层标高 | 立面各层标高 | 剖面各层标高 | 与 B1 形成三角互证 |
| C3 | 女儿墙高度 | 立面女儿墙 | 剖面女儿墙 | 屋面工程量、防水翻边 |
| C4 | 屋面形式 | 立面檐口轮廓 | 剖面屋面坡度/形式 | 屋面面积（坡度系数） |
| C5 | 外窗竖向位置 | 立面窗上下口标高 | 剖面窗上下口 | 与 B3 互证 |

### D 组 · 建筑 × 结构（6 项 · **v4.6.1 新增，房建最贵的一组**）

前三组全是"建筑三视图之间"。但真实事故里，**建筑图与结构图对不上**的频率远高于
平面与立面不符，而后果也大得多——它一错就是一整层或一整个分部，不是一扇窗。

| # | 校验参数 | 建筑侧取什么 | 结构侧取什么 | 后果 |
|---|---|---|---|---|
| D1 | **轴网与总尺寸** | 建筑轴网开间/进深、总长总宽 | 结构轴网、总长总宽 | 楼板、砌体、装修、幕墙、屋面面积的**总开关**；差 3% 则全部面积类量等比例错 |
| D2 | **构件厚度** | 建筑图上的板厚/墙厚（含面层说明） | 结构图的板厚/墙厚/底板厚 | 混凝土、模板、砌体、净高四类量同时受影响 |
| D3 | **梁底标高 vs 建筑净高** | 房间净高、吊顶完成面 | 梁底标高 | 吊顶标高、机电净空、梁侧模板 |
| D4 | **楼梯踏步数与层高** | 建筑楼梯详图踏步数与踏步高 | 结构楼梯板标高 | **踏步数 × 踏步高 = 层高**，不闭合则整栋楼梯混凝土、模板、面层、栏杆全错 |
| D5 | **基础埋深与 ±0.000** | 建筑 ±0.000 与室外地坪关系 | 基底/承台底标高 | 土方、基础混凝土、回填、防水、支护的分部量开关 |
| D6 | **层数与标准层界定** | 建筑层数、标准层范围 | 结构层数、标准层范围 | 体系乘数的前提（H28）；层数错一位就是整楼偏差 |

> **D4 的写法**：`value` 填「踏步数 × 踏步高」的乘积，与层高比。20 级 × 165 = 3300，
> 层高标 3300 → PASS；若层高是 3400，差的 100 会一路带到平台标高、梯梁、栏杆。
> 这一项比 B4（楼梯净高）更硬：净高是合规问题，踏步数是**工程量问题**。

**结构项目（道桥/铁路）的对应做法**：把"平面×立面×剖面"换成
「平面（PLAN）× 纵断面（PROFIL EN LONG）× 横断面（COUPE TRANSVERSALE）」，
校验参数换成：跨径与梁长、墩台中心里程、支承垫石标高、桥面横坡、墩身收坡。
**参数名不同，方法完全一样**——都是"同一物理量在两个视图里各有一个值，必须相等"。

## 二、六条规则

| # | 规则 | 判据 | 违反时 |
|---|---|---|---|
| **R1 溯源** | 每个取值必须带「图号 + 页码/图签 + 图面位置」 | 三项缺一即不可比对 | 该侧记 `NO_TRACE`，判 `UNVERIFIABLE` |
| **R2 同基准** | 两侧必须同一基准：同一标高系统、同一单位、同一比例参照 | 基准不同须先换算，**换算必须显式记录系数与来源** | 拒绝静默换算 → `UNVERIFIABLE` |
| **R3 容差** | 按参数类别给容差，**不给统一容差**（见 §三） | 差值 ≤ 容差判 PASS | 超容差判 `CONFLICT` |
| **R4 缺失不等于跳过** | 一侧没有该参数时，判 `UNVERIFIABLE` 并写明缺哪侧 | **禁止**把"另一侧没写"当成"一致" | 缺项必须进报告，不得静默 |
| **R5 剖切匹配（人工前置）** | 剖面必须切到该参数所在位置 | 剖面未经过该房间/该跨 → 不可比 | **由填表人判断并在 `loc` 里写明剖切位置**；工具不做自动匹配，判不了就标 `N/A` 或 `UNVERIFIABLE` |
| **R6 同范围** | 两侧必须同一计量范围：单层/全楼、单幅/双幅、单座/全桥 | 范围不同 → 数值必然不等，但**两侧都没有错** | 填 `scope`；两侧 scope 不同判 `UNVERIFIABLE（范围不同）`，**不判 CONFLICT** |

**R6 是 v4.6.1 补的一条，不补会常年假红**：门窗表是"全楼"，平面图是"本层"；
桩位图是"单幅"，承台图是"双幅合计"。拿全楼表对单层点数，按计数 ±0 判必然冲突——
而这是**假冲突**，代价是整组计数项被判死，跑两次没人再看。

**R4 是这条门禁的诚信底线**：22 项里通过 3 项、缺 19 项，不能报"3/3 通过"。
必须报「通过 3 / 冲突 0 / 无法校验 19」，并列出 19 项缺什么。

## 三、容差表（**不用统一容差**）

| 参数类别 | 容差 | 理由 |
|---|---|---|
| **标高、层高、总高**（两侧都是标注值） | **±0** | 标高是设计给定的整数，差 1 mm 就是两个值，不存在"粉刷层"解释 |
| **标高（派生值 vs 标注值）** | **±10 mm** | 分段取整累加（3.30×3=9.90）对总标注（9.89）天然有舍入差；用 ±0 会把每条合规高程链都判死。**派生侧必须在 spec 里写 `tol: elevation_derived`** |
| **结构尺寸**（断面、跨径、墙厚、板厚） | **±0** | 施工图精度不允许用 5 mm 容差放跑真错 |
| **装修 / 面层尺寸**（窗台高、吊顶、分格） | **±5 mm** | 建筑做法层允许的施工偏差 |
| **角度、坡度** | ±0.1%（或按图纸标注精度） | 坡度错会放大到面积 |
| **计数类**（窗数、门数） | **±0（整数严格相等）** | 数量不存在容差；不等就是漏数或重复 |

> 建筑口径常用的 ±5 mm **不能**套到结构与标高上——那会把"层高 3600 vs 3300"
> 这种真错按"公差"放过去。这是本表与原版（建筑门窗校验）最大的口径差异。
>
> 反向的错也要防：拿 ±0 去比派生值，会把**每一条合规**的高程链判成冲突。
> 两个方向都是"容差用错"，结果都是门禁被弃用。
>
> **容差不是越严越好。** 严到出假红，等于没有门禁；松到放过真错，等于假绿。
> 唯一正确的做法是**按参数性质分类**，并让每一类都能说出理由。

## 四、版本闸（**只拦"同一图号两个内容"，不拦"不同图册版本不同"**）

```text
同一图号（a.sheet == b.sheet）且 sha256 不同
    → RULE_CONFLICT：这才叫版本分裂，必须先定版
a.rev != b.rev（不同图册）
    → 继续比，标「跨版本对照」：
       · PASS 记为「跨版一致」，不是「同版确认」
       · CONFLICT 提示先核修订表/修订云线，再判是不是图纸矛盾
--strict-rev（可选）
    → 恢复"rev 不同即停"，仅在合同明文要求同版对照时用
```

**为什么改成这样**（v4.6.1，这是本版两处口径修正之一）：

建筑 `CD-101 Rev C`、剖面 `CD-301 Rev B` 是**正常出图状态**——平面上个月改过，
立面三个月没动。旧口径"rev 不同即 RULE_CONFLICT"会让项目中期起 22 项**全部**判阻塞，
矩阵永远出不了 PASS。而门禁一旦长期无输出，第三次跑就会被跳过。
**这不是谨慎，这是制造假红。**

真正的定版依据不是比 rev 字母大小（法语区还有 `Indice A/B/C`、`0/1/2`、`V0/V1`、
`Additif n°`，大小与新陈没有对应关系），而是：

1. **修订表**（Tableau des révisions / Revision Schedule）与 transmittal：哪一版是最近一次正式发行；
2. **修订云线**（nuage de révision / revision cloud）：**该参数所在区域是否被云线覆盖**。
   未覆盖 → 该参数仍是上一版基准，跨版直接比是安全的；覆盖了 → 以覆盖它的那一版为准。

第 2 条是全流程的关键，也是工具做不了、必须人看的一步——所以工具只负责**标出来**，
不替人下结论。

版本信息从建册台账取（`build_input_register.py` 的 `rev` + `sha256`），
**不要求重新计算哈希**——建册时算过就用建册的，没算过判 `NO_TRACE`。

## 五、六种结论

| 结论 | 含义 | 处置 | 退出码 |
|---|---|---|---|
| `PASS` | 两侧有值、同基准、同范围、差 ≤ 容差 | 无需动作（跨版本时会另标） | — |
| `CONFLICT` | 两侧有值且差 > 容差 | **挂 OI + 该参数的下游量不得出交付值**（H33） | 有 ≥1 项 → **1** |
| `UNVERIFIABLE` | 缺一侧 / 缺溯源 / 不同基准 / **范围不同** / 数值写法歧义 | 挂 OI，**继续算其它项**（不打断协议） | 不单独致红，但必须计数 |
| `RULE_CONFLICT` | 同一图号两个内容 | 先定版，比不了 | 不单独致红，但必须计数 |
| `UNFILLED` | 模板一个字没填 | 补填，或写 `note="N/A+理由"` | 计入"没查" |
| `N/A` | 经判断不适用，`note` 已声明理由 | 单列存档 | 全篇 N/A → **2** |

**没有 `SHEET_MISMATCH` 这个结论。** 剖切位置是否匹配由填表人判断（R5），
判不了就写 `N/A` 或 `UNVERIFIABLE`——工具不产出它无法验证的结论。

**`UNVERIFIABLE` 不许折算成 PASS。** 它是"没查"，不是"没问题"——
与门禁总结里"未运行不得计入通过"是同一条纪律。

**退出码**：`0` 至少有一项通过且无冲突／`1` 有 CONFLICT／`2` 无法运行或**一项都没通过**
（全篇未填、全篇 N/A、全部不可比都算"没查"，一律 2）。

## 六、强制范围（**该跑的时候跑，不该跑的时候明确说不适用**）

| 项目类型 | 要求 | 说明 |
|---|---|---|
| 房建 / 多图册项目 | **强制** | 平面、立面、剖面分图绘制，天然存在三视图不一致 |
| 道桥 / 铁路（有纵断面 + 横断面 + 平面） | **强制** | 用 §一末尾的对应参数集 |
| 单图册、无第二视图可比对 | **判不适用（N/A）**，不报红 | 如本项目 VIADUC 三张图虽有平面/纵断/总装，但**无独立横断面册**，横断面项判 N/A |
| 只有一张图的项目 | N/A | 不得为了"跑过"而虚构校验对 |

**N/A 必须写进报告**，不能静默——"本次不适用（图册内无立面/剖面可比对）"比
"永远跑但永远跳过"诚实。

## 七、与既有门禁的关系（顺序不能反）

```text
chain_check（G-CHAIN）     一张图内：尺寸链闭不闭合
        ↓
cross_drawing_check（G-XD） 图与图之间：同一参数两个值是否一致
        ↓
gate_basis_freshness（G-FRESH） 基准可不可信
        ↓
gate_drawing_basis（G-DB）  量 vs 基线
```

**从内到外逐层收口**：图内不闭合谈图间一致没有意义；图间不一致时"量与基线一致"也是假的
（基线本身可能是被读错的那一版）。顺序颠倒会得到"全部通过"的假结论。

## 八、工具用法

```bash
# 1) 生成校验矩阵模板（22 项骨架，人工填两侧取值）
python scripts/cross_drawing_check.py init --spec takeoff/cross_check.json --project "<项目名>"

# 2) 跑校验
python scripts/cross_drawing_check.py run --spec takeoff/cross_check.json \
        --out takeoff/cross_check_report.json

# 3) 只看标高类（B1 + C2）
python scripts/cross_drawing_check.py run --spec takeoff/cross_check.json --only B1,C2

# 4) 自证（含反向断言：合法的等价项不得出现在 findings 里）
python scripts/cross_drawing_check.py selftest

# 5) 合同要求同版对照时才加 --strict-rev
python scripts/cross_drawing_check.py run --spec takeoff/cross_check.json --strict-rev
```

退出码：`0` 至少一项通过且无冲突／`1` 有 CONFLICT／`2` 无法运行或一项都没通过。

**报告必须含六个数**：`通过 / 冲突 / 无法校验 / 版本分裂 / 不适用 / 未填`，
跨版本对照另报一项。只报"通过 N 项"等于隐瞒了没查的部分。

**数值写法**：法语图册的 `3,60` 按 3.60 解析，`1 250` 按 1250 解析（空格是千分位）。
逗号后 3 位（`3,605`）判**歧义**而不是猜——可能是 3.605，也可能是 3605，猜错就是 1000 倍。

## 九、与原版（Quick 套件）的差异

| 项 | 原版 | 本版 | 为什么改 |
|---|---|---|---|
| 容差 | 统一 ±5 mm | 标高/结构 ±0、装修 ±5 mm | 建筑口径套到结构上会放跑真错 |
| 版本 | 无 | 只拦"同图号两个内容"；跨图册 rev 不同标「跨版对照」继续比 | 旧口径"rev 不同即停"会让项目中期 22 项全阻塞——制造假红，比不设闸更糟 |
| 覆盖 | 门窗立面为主（16 项） | 增 D 组建筑×结构 6 项（轴网/构件厚度/梁底净高/踏步数/基础埋深/层数） | 房建真实事故多在建筑×结构之间，且一错就是一整层 |
| 结论态 | 一致/不一致 | 六值：PASS / CONFLICT / UNVERIFIABLE / RULE_CONFLICT / UNFILLED / N/A | "没法比"和"比了不一致"必须分开；"没查"和"查了没通过"更要分开 |
| 语言 | 中文图名 | 附法语图名对照（COFFRAGE/FERRAILLAGE/COUPE/ÉLÉVATION） | 本项目为法语图册 |
| 交互 | 发现 ≥3 项不一致就停下来问 | **全部进 OI 台账并继续算**，只在改变分部量 ≥10% 时停 | 大项目上停下来问 3 个问题 = 把 20 分钟评审拆成 3 天往返 |
| 范围 | 无条件必跑 | 房建/多图册强制；单图册判 N/A 并写明 | 门禁已 20+，再加无条件必跑会整体被跳过 |

---

> **一句话**：跨图校验不是为了多抓几个错，是为了避免"算完一整层才发现层高是另一个数"。
> 它必须在算量**之前**跑——算完再改，代价是一个数量级。
