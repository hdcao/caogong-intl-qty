# 输入消化 · 数据源语义 · 门禁执行凭证

> **v4.6.2 新增**。本文件回答一个问题：**为什么迭代了很多轮，同类错误还在犯？**
>
> 结论：不是知识不足，是三个机制缺口。三节分别对应一个缺口与补强方案。
>
> 加载时机：**项目开工前**（§1）、**拿到任何外部清单/信息表时**（§2）、**每次交付前**（§3）。

---

## §1 输入消化（缺口一：算之前没看清要算的是什么）

### 1.1 现象：问题总是在"算"的过程中被偶然发现

本项目 21 轮迭代，反复出现的不是算错，而是**该在消化阶段发现的事，拖到算量阶段才暴露**。

| 实际事故 | 暴露轮次 | 代价 | 消化阶段能否避免 |
|---|---|---|---|
| 箱涵信息表 `DISCHARGES(m3/S)` 是**流量列**，被当尺寸列 | 第 12 轮 | 已按错列义算两轮，洞身 5,356 vs 正确 9,191（−42%） | ✅ 看一眼表头单位即可 |
| 照明负荷表每张含 **2~3 个配电柜**，被按"一图一柜"解析 | 第 18 轮 | 漏 11 个面板，负荷 215 vs 693 kW（−69%） | ✅ 数一下每张几个柜 |
| 洞口防护表 `B=3.00` 是 **W=1m 时的示例值**（实为 3×W 函数） | 第 19 轮 | 防护 234.9 vs 336.1 m³（−30%） | ✅ 读 WHERE 注解 |
| 外部清单整列含 **×1.05 富余系数** | 第 21 轮 | 所有对比带 5% 系统性假差异 | ✅ 逐行整除测试一次 |
| 台账由 125 行被脚本覆盖成 62 行 | 第 19 轮 | 全部修正被冲掉，需重放 | ✅ 改前先看行数 |
| 图纸实际是 **CAD 数据源**，却在 PDF 上做了三轮矢量提取 | 早期 | 三轮白做 | ✅ 开工先问"有 DWG 吗" |

**共同特征：这些都不是"算"错了，而是"算错对象"。** 且每次都在同一位置再犯一次——
因为没有机制强迫在算之前把这些看清。

### 1.2 根本原因：三个结构性缺陷

**① 把"读过"当成"消化过"**

"图纸我都打开了""标书我扫过了"——这只证明文件被访问，不证明其约束被提取。
消化的产物应该是**可核验的结论 + 出处**，不是"我看过了"这个记忆。

**② 分工上没有人对"输入理解"负责**

传统分工里，读图的人负责量，复核的人负责对数。**但"这个表的第 3 列到底是什么"
不属于任何人的交付物**。它默认由读图人顺带解决，于是最容易被跳过。

**③ 缺少"未消化完不许开工"的硬闸**

所有压力都指向"尽快出量"。没有闸门时，"先算起来遇到再说"永远是最省事的选择——
直到返工。而返工的代价从不计入当初"省下的时间"。

### 1.3 方案：把消化做成一等交付物

#### 流程机制

```
第 -2 步 输入消化（不产出任何数量）
   ↓  input_digest.py verify 必须 exit 0
第 -1 步 测量策略卡
   ↓
第 0 步  建册
   ↓  ...
```

**四条硬规矩**：

1. **未消化完不得出量**。verify 非 0 → 只能做探索性试算，成果标 `DRAFT`，
   交付物首行须写明"本次为探索性试算，未完成输入消化"。
2. **结论必须带出处**。`--source` 必填，写"按合同"不合格，须写"标书 Vol.2 p.147 §3.4"。
3. **标书与图纸交叉读**。互指条款（图纸"见规范"↔规范"详图纸"）必须落到一端并登记。
4. **消化阶段的问题立即分流**：口径冲突→OI、图纸缺件→RFI、范围不明→**停下问**。

#### 十二项必答清单

| ID | 分类 | 必答内容 | 不合格示例 |
|---|---|---|---|
| D-01 | 范围 | 分部/标段清单，**含排除项与依据** | "按图纸算" |
| D-02 | 范围 | 计量规则 + 版本 + 项目修订条款号 | "按国际惯例" |
| D-03 | 范围 | 量差/变更/暂列的合同特别约定 | "合同没细看" |
| D-04 | 输入 | 图纸目录树已列全，缺件单列 | "文件都在文件夹里" |
| D-05 | 输入 | 标书通读，关键条款摘到页码 | "标书太长没看完" |
| D-06 | 输入 | 文字层状态已判型（text/扫描/转曲） | "PDF 应该能直接读" |
| D-07 | 输入 | **信息表表头列义已逐列确认** | "表头挺清楚的" |
| D-08 | 输入 | 外部清单是否含系数，已归一 | "数字直接用" |
| D-09 | 交付 | 交付物清单与格式 | "出个工程量表" |
| D-10 | 交付 | 精度（小数位/允许偏差/敞口上限） | "差不多就行" |
| D-11 | 交付 | 验收人与放行权限 | "AI 出就行" |
| D-12 | 交付 | **明确不审的范围及原因** | 沉默（会被读成"都查了"） |

#### 工具支持

```bash
python scripts/input_digest.py init   --root . --project "<名>" --drawings <目录> --tender <标书>
python scripts/input_digest.py set    --file takeoff/input_digest.json \
        --id D-07 --answer "..." --source "标书p.147" --by 张三
python scripts/input_digest.py issue  --file ... --id D-07 --kind RFI --text "..."
python scripts/input_digest.py verify --file ... --strict   # 交付前必跑
```

#### 评审节点

| 节点 | 时机 | 谁签 | 过闸条件 |
|---|---|---|---|
| **消化评审** | 开工前，一次性 | 读图人 + 复核人**双签** | 12 项全 DONE、有出处、无未决阻断项 |
| **增量消化** | 每收到新图/补遗 | 接收人 | 新增图纸已登记，受影响项重开 |
| **消化回溯** | 每轮修订结束 | 复核人 | 本轮新发现的"本该早知道"事项已回填到清单 |

## §2 数据源语义体检（缺口二：门禁只验内部自洽）

### 2.1 现象：算得对，但算错了东西

原有 40+ 门禁全部在验**内部自洽**——算式对不对、单位对不对、跨表对不对。
它们对下面这类错误**完全无效**，因为算式本身没有任何问题：

| 错误 | 输出上看起来 | 实际 |
|---|---|---|
| 把流量列当尺寸列 | 算式完整、单位正确、汇总平衡 | 差 42% |
| 把示例值当定值 | 同上 | 差 30% |
| 假设一图一柜 | 同上 | 差 69% |
| 未识别 ×1.05 系数 | 同上 | 系统性偏 5% |

**"算得对但算错了东西"在交付物上不留任何痕迹**，这是它比算错更危险的原因。

### 2.2 方案：G-SRC 门禁

```bash
# ① 看列 + 统计指纹（不改数据）
python scripts/gate_source_semantics.py list-columns --file <清单>.xlsx --sheet Sheet1

# ② 体检可疑系数与量纲冲突
python scripts/gate_source_semantics.py table --file <清单>.xlsx --sheet Sheet1 --out out/src_check/

# ③ 生成声明模板（人填列义）
python scripts/gate_source_semantics.py declare --out out/src_check/decl.json

# ④ 用声明校验收数
python scripts/gate_source_semantics.py verify --file <清单>.xlsx --declare out/src_check/decl.json
```

**判据设计（关键）**：不能只看"可整除某系数的比例"，因为工程量本身常是整数，
对 1.05 会自然偏高。实测校准（本项目 718 行真实数据）：

```
×1.050 → 59.6%      ×1.100 → 3.1%      ×1.150 → 1.4%
```

1.05 与其它档拉开 **20 倍**——这才是可靠信号。故判据为：

- 命中率 ≥ 85% → 可疑
- 命中率 ≥ 40% **且** ≥ 5 倍于次高系数 → 可疑
- 其它 → 不报（避免误咬干净表）

**三条阻断**：数值列未登记语义 / `confirmed_by` 未由人签署 / 声明 gross 但系数无效。

### 2.3 净量原则（项目既定）

> **一律按不含富余系数的净量出数。**

来源清单/图纸量表若含损耗、富余、超挖、搭接系数，**必须先 ÷ 系数归一到净量再进入任何换算**。
含系数出数有两个后果：

1. 与其它来源对比时产生**固定比例的系统性假差异**，把真实量差淹没；
2. 进入报价链后被重复叠加（清单含 5% + 报价再加 5% → 实际 10.25%）。

## §3 门禁执行凭证（缺口三：规则写了但没跑）

### 3.1 现象："写进技能包" ≠ "会被加载" ≠ "会被执行"

这是本项目最深的一条教训，且**已被验证过三次**：

1. 某一轮：`G-X0` 的规则、门禁、脚本三样齐全，仍然写出"交叉检核通过（独立代码路径）"，
   实际是**自建对照表、根本没跑脚本** → 13 项全 0.000% 的假通过漏网。
2. 某一轮：教训刚写进记忆文件，**下一轮同类错误第三次重犯**。
3. 某一轮：改了台账没同步基准，门禁连报 6 次不同步——这次起作用了，因为**真的跑了**。

**结论：规则的有效性不取决于写得多好，而取决于"没跑就出不了交付物"。**

### 3.2 方案：G-RUN 执行凭证

```bash
# ① 按档位生成必跑门禁清单
python scripts/gate_execution_receipt.py init --root . --tier 全量 --out takeoff/gate_receipt.json

# ② 每跑完一条就记录（应由运行器自动写，不许手填 exit_code）
python scripts/gate_execution_receipt.py record --file takeoff/gate_receipt.json \
    --id G-CHAIN --exit-code 0 --rows 42 --expect-rows 42 \
    --cmd "python scripts/chain_check.py run --spec ..."

# ③ 交付前验收（唯一放行闸）
python scripts/gate_execution_receipt.py verify --file takeoff/gate_receipt.json --strict
```

**三条硬断言**：

| 断言 | 理由 |
|---|---|
| required 门禁缺失 → FAIL | 没记录 = 没跑，不许默认通过 |
| `rows_checked == 0` → FAIL | 零行等于没检（与 SKILL.md 零行守卫一致） |
| `rows_checked < rows_expected` → FAIL | 分母缩水 = 部分判据未被验证 |

### 3.3 三条反自欺规则

这三条不是技术规则，是**表达纪律**，但没有它们，技术门禁会被话术绕过：

**① 没用凭证不许说"全部门禁通过"**

汇总只能写三栏：`通过 N 项 / 未运行 K 项 / 待确认 M 项`。
`未运行 > 0` 时，"通过"这个词只能跟在具体门禁号后面，不能出现在总结句里。

**② 不许把"没发现问题"表述为"没有问题"**

零发现与干净在输出上无法区分。必须写"未发现"+"检查了什么范围"+"什么没查"。

**③ 不许用"已关注/持续跟踪"代替责任处置**

非 PASS 项必须三态之一：**已闭合 / 阻断 / 挂账**，且挂账须有责任人与期限。

## §4 如何验证改进效果（不是"感觉好多了"）

改进是否有效，必须能被**独立复现**。四条可量化指标：

| # | 指标 | 基线（改进前） | 目标 | 测法 |
|---|---|---|---|---|
| 1 | **同位置重犯率** | 同类错误 ≥3 次（有记录） | **0 次** | 每轮结束把新错误归类，看是否落在已登记类别 |
| 2 | **错误暴露轮次** | 平均第 12~18 轮才暴露 | **消化阶段即暴露** | 记录每个问题"首次出现位置"在消化/算量/复核/交付哪一阶段 |
| 3 | **返工占比** | 未统计 | **<20%** | 返工工时 ÷ 总工时 |
| 4 | **门禁真实执行率** | 无法证明 | **100% 有凭证** | `gate_execution_receipt.py verify` exit 0 |

**回归测试（可自动跑）**：

```bash
python scripts/test_source_semantics.py   # 6 用例：能抓真实事故 + 不误咬干净表
python scripts/test_input_digest.py       # 5 用例：未消化/无出处/AI代签 必须阻断
python scripts/test_execution_receipt.py  # 5 用例：缺项/零行/FAIL/无凭证 必须阻断
```

**验收标准**：三组自测 `用例覆盖 x/y` 且全部符合预期，方可在交付物中写
"改进已验证"；否则只能写"改进已实施，效果待观察"。

## 一句话

**前 21 轮的教训可以浓缩成一句**：问题不是"算不出来"，而是"太晚才看清要算的是什么"。
本文件三节分别对应"看清"（§1）、"看清数据源"（§2）、"证明真的看过了"（§3）。
