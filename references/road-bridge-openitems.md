# 道桥类项目开项清单（Road & Bridge Open-item Checklist）

> **用途**：算量前用它开项，交付前用它**复核漏项**。
> 每件主体构件都**拖着一条固定的尾巴**——清单的作用就是逼你把尾巴一起列出来。
>
> 编制依据：阿尔及利亚 ANESRIF 铁路桥项目（VIADUC PK295+300，APS 阶段）
> 与沙特 SPARK 东绕城公路 EPR 项目（V4→V7 四轮审核）的实测漏项。

---

## 0. 怎么用

### 0.1 三步走

```
① 开项   —— 按清单逐条建 CBS 编码，空的也要建（标"本项不设"）
② 取证   —— 每条填图号 + 图面位置 + 方向 + 口径（绘图员签名）
③ 复核   —— 交付前反向扫一遍红旗表（§7），逐条打 ✅/❌/⚠️
```

### 0.2 三态标记（不许留空）

| 态 | 含义 | 要求 |
|---|---|---|
| **✅ 已计** | 有量、有出处、有签名 | 出处可定位到图面区域 |
| **⚠️ 待核** | 图面缺失或口径存疑，**已挂 RFI** | 必须写 RFI 编号 |
| **❌ 漏项** | 确认应该有却没进清单 | 必须补列或写明"不在合同范围"并登记 |

**禁止**：留白、写"待定"、写"后续补充"——这些等于没做。

### 0.3 机器比对

```bash
python scripts/drafter_qto.py coverage --file takeoff/register/readings_桥梁.csv \
       --catalog road-bridge --json out/open_items.json
```

### 0.4 编号是模板编号，与项目 CBS 编码无关

本清单用模板编号 `{分部}-{层}-{序号}`（如 `A-2-3` = 桥梁 A · 第 2 层第 3 项），
**与具体项目的 CBS 编码无关**。项目落地时在台账里**并排登记两列**：

- `template_id` —— 抄本清单的模板编号
- `cbs_code` —— 登记该项目自己的 CBS 编码

例（PK295+300）：`A-2-3` 桥台台身混凝土 → `cbs_code = CBS-OVA-I03`

`drafter_qto.py coverage` 两列都认（任一列命中即算已登记）。

## 1. A · 桥梁（Bridge）

桥梁是**漏项与误判最高发**的分部。**先判体系，再数构件。**

### 1.0 体系判定（算量之前的必答题，逐桥/逐座）

| 要判定的 | 取值来源 | 误判代价（实测） |
|---|---|---|
| **上部梁型** | 梁断面详图 1:30~1:10 | T 梁 / I 梁 / U 梁 / 箱梁 / 预制板+现浇层组合判错 → 桥面板、梁断面、施工方法全错 |
| **桥面板构成** | 板座详图 + NOTES | 预制 plank 与现浇层**必须分列**，计价口径不同 |
| **单幅 / 双幅** | 平面图 `SOUTH/NORTH CARRIAGEWAY`、支座表 | 双幅算成单幅 → 差 2 倍 |
| **基础形式** | 桥台剖面（扩大基础 vs PILE CAP） | 把扩大基础当桩基 → 凭空造出 900 m 桩 |
| **斜交角度** | 平面图角度标注 | 沿路线长 vs 沿桥轴长差 1/cos θ |
| **逐座差异** | 每座单独的设计图 | 同为 2500×1500 箱涵，壁厚 450/400 与 400/350 并存 |

> **绝不允许用一个构件的参数外推同类构件。**
> 实测：桥1 梁断面 0.90 m² 套到桥2 → 体系与断面都错。

### 1.0.1 「禁止外推」的两个层级（易误读，必须分清）

| 层级 | 规则 | 实测理由 |
|---|---|---|
| **同专业 · 同类型构件**<br>（桥1 ↔ 桥2；涵 A ↔ 涵 B） | **必须逐座直读**，禁止用一个构件的外形参数外推另一个 | 同为 2500×1500 箱涵，壁厚 450/400 与 400/350 并存；承台厚 1600（有盖梁）与 1500（无盖梁柱式墩）并存，**都不是笔误** |
| **跨专业**<br>（房建 ↔ 道桥；MEP ↔ 土建） | **禁止引用**他专业的实测数字与修正幅度 | 指标与结构体系、荷载、工法强相关，跨专业外推没有物理意义，且会制造**伪精确** |

**可以同时沿用的**（不构成外推）：设计说明明确写"适用于全桥/全部同类构件"的
**通用构造做法**——前提是它有图号与条文出处，且逐座核对过无单独变更。
（层级规则全文见 `disciplines-coverage.md` §2.1。）

### 1.0.2 排除项：道砟与轨道工程

道砟（ballast）及轨道上部结构属**轨道工程（06.VOIE）**，**不并入桥梁清单**。
桥上 0.80 m 仅为**道床厚度，参与高程链闭合**，但其量归轨道专业。

> 排除项同样要写"为什么不算"，否则下次复核会当成漏项补进来 → 重复计量。

## 4. D · 排水（Drainage & Sewerage）

排水是**口径不声明即失效**的分部：同一段管，量到井壁还是量到井中心，
差一个井径；DN 与材质不逐段直读，清单就是一堆无法复核的数字。

| # | 开项 | 图证出处 | 漏项红旗 |
|---|---|---|---|
| D-1-1 | 雨水管（DN / 材质 / 长度） | 排水平面 + 纵断面 | **先声明计量口径**；DN / 材质逐段读，禁全线套一种 |
| D-1-2 | 检查井（尺寸 / 深度分档） | 排水平面 + 井表 | **按深度分档计价**，不是一口价 |
| D-1-3 | 雨水口 / 连接管 | 雨水口大样 | 连接管长度常整项漏 |
| D-1-4 | 管基 / 包封 / 支墩 | 管道基础详图 | **整项漏高发**；管件与管道分开计量 |

**红旗 · 管道计量口径**：管长算到**井壁**还是**井中心线**，两种口径每座井差一个井径，
一公里管线累计就是几百米。开项时必须把口径原文抄进 `method` 列
（`to wall of chamber` / `centre to centre`），是否扣井宽一并写清。
口径没声明的管长属于不可复核读数，不许进汇总。
中东项目上业主与承包商两份清单对不上，多半差在口径而不是算错。

**红旗 · 检查井按深度分档**：井不是"一座多少钱"的一口价。
实测（沙特 SPARK 东绕城 EPR）：井量按**深度分级表**计价，**分级表才是量源**。
做法：拿井表里的井顶/井底高程逐座算埋深 → 落档 → 档内计数；
等级漏一点，深井的开挖、井筒加长与重型井盖差价就全部让出去。

**红旗 · 管基 / 包封 / 支墩**：这一层没有"形状直觉"，它不在排水平面图上而在
管道基础详图里，按平面图数完管子就收工 → **D-1-4 整项漏**。
另注意管件（弯头、三通、变径）与管道**分列**：管道按延长米，管件按个，
两者口径不同，合并成一个综合单价后无法再拆开复核。

## 5. E · 机电与照明（MEP & Street Lighting）

**本分部实测整组漏最高发**。根子是清点方向：从"灯"往回数，数到配电盘就停了，
电源侧整层没进清单。正确做法是**顺着电流从上往下数**：
中压进线 → 箱式变电站 → 配电盘柜 → 回路电缆 → 末端灯杆灯具 → 接地与基础。

| # | 开项 | 图证出处 | 漏项红旗 |
|---|---|---|---|
| E-1-1 | 中压电缆 / 箱式变电站 PS | 照明系统图（电源侧） | **只计末端必漏电源侧** |
| E-1-2 | 配电盘柜 FP / 照明配电盘 | 回路表 | **一页图可能排两个盘**，回路要按盘归属 |
| E-1-3 | 低压电缆（4C×N） | 回路表逐回路长度 | N 按回路直读，禁全线统一截面 |
| E-1-4 | 接地导体 ECC（与主缆等长） | 回路表 | **整项漏高发**：ECC 与主缆 1:1 |
| E-1-5 | 保护管 / 手孔井 / 电缆沟 | 敷设详图 | 手孔**按型分**；保护管沿路径长度常漏 |
| E-1-6 | 灯杆（按杆型分型） | 图例 + 布置图 | **不许把杆型合并成两种** |
| E-1-7 | 灯具（头数 ≠ 杆数） | 图例（每杆灯具头数） | **头数正好等于杆数 = 疑似未展开** |
| E-1-8 | 灯杆基础 / 锚栓 / 法兰 | 基础详图 + BAR BENDING SCHEDULE | 高杆与 12m 杆**差一个量级** |
| E-1-9 | 接地极 / 接地干线 | 接地详图 | 常与 ECC 混为一谈，两者必须分列 |
| E-1-10 | 桥下照明 / 利旧改造 / 既有拆除 | 图册子目录 | **整组漏** |

**红旗 · 只计末端必漏电源侧**：实测（沙特 SPARK 东绕城 EPR，V6）：V6 只计了 FP 馈线柜，
**17 座 PS 箱式变电站**与**全部接地系统**一个没进清单——因为清点时是从灯往回数，
数到配电盘就停了。复核动作：把回路表里每个 FP 往上游追一级，直到中压进线点，
缺一级就是漏项，不许停在"看起来到头了"的那一级。

**红旗 · ECC 与主缆等长（1:1）**：照明回路表里每回路都有独立 ECC 栏，且与主缆**等长**。
实测该项目 ECC 共 **43,566 m 整项漏**。判据极简：`ΣECC ≈ Σ低压电缆`；
台账里 ECC 为 0 或只有零星几百米，就是那一栏没读。禁止把 ECC 摊进电缆综合单价。

**红旗 · 灯具数 ≠ 杆数（符号—实物 N:1）**：图例上一个符号是一根杆，
一根 25 m 高杆带 **6 套**灯具。实测曾把灯具数直接当杆数用（另见文末红旗表第 2 条）。
判据：灯具总数 ÷ 杆总数落在 1.5~6 之间属正常，正好 **1.0** 就是 N:1 未识别。
杆数决定基础数量与电缆回路数，灯具数决定安装与光源，**两行并列，不许合并**。

**红旗 · 杆型不许合并**：同一条路实测**至少 6~7 种杆型**（高杆、单臂、双臂、
弯道加长臂……），粗放开项会合并成"高杆/普通杆"两种，而它们的造价差一个量级：
25 m 高杆基础 **3M×3M**（≈**8.5 m³** 混凝土 + **1.23 t** 钢筋/座），
12 m 杆基础 **800×800**（≈**0.8 m³**），**混算差 3.9 倍**。
锚栓与法兰同样按杆型分套，杜绝"每座平均"。

**红旗 · 一页图可能排两个盘**：实测 10 张回路图覆盖 FP-01~FP-17，平均一页不止一个盘。
抄回路前先判这份回路表属于哪个盘；把 A 盘的回路挂到 B 盘，
回路数、电缆长度、敷设分区会整串错位，且错位后表面自洽、极难发现。

**红旗 · 桥下照明是独立分部**：图册里通常挂在 `06.STREET LIGHTING/UNDERBRIDGE LIGHTING/`
这类**子目录**下，与桥上照明不同图、不同回路、不同安装方式（多为吸顶/壁装支架，
不用落地基础）。翻图册只翻根目录必漏。
同组的**利旧改造与既有拆除**同理：改造项目的拆除量通常写在另一本图或接口条件里，
不写不等于不计量，现场一定会发生 → 登记 ⚠️ 待核远好过沉默。

## 6. X · 措施与其他（Temporary Works & Preliminaries）

**本分部的量不来自图纸，来自工法与工期。** 图上没有模板周转次数、降水台班、
脚手架站立的时长，所以这里每一条默认 `source = method`，
**未经人工逐条确认不许出数**。

| # | 开项 | 图证出处 | 漏项红旗 |
|---|---|---|---|
| X-1-1 | 模板（按构件展开面积） | 构件几何 | 周转次数须人工确认，禁自取 |
| X-1-2 | 支架 / 便道 / 围挡 | 施工方案 | 工法依赖，须人工确认 |
| X-1-3 | 降水 / 排水 / 土方外运 | 方案 + 工期 | 工期与台班须人工确认 |
| X-1-4 | 交通导改 | 接口条件 | 须人工确认 |

**红旗 · 不许用"通常 / 惯例"取值**：模板周转几次、降水开多少台班、支架站几个月，
图纸上都没有。任何按"通常 3 次""惯例 2 个月"填出来的数都不是读数，是**推定**：
必须标 `source=method` 进敞口台账、写明由谁确认；无人确认就保持 ⚠️ 并挂 RFI。
与其他分部不同，这里问不出答案也是常态——那就把"未确认"这个事实本身写进交付文件，
而不是替它编一个体面的数字。

**红旗 · 模板按构件展开面积**：模板不是"混凝土量的某个倍数"，是逐构件的接触面积。
同一清单里承台、墩柱、盖梁、梁体、涵身的模板系数各不相同，
用一个综合系数反算，被追问"依据"时答不上来。开项到构件级：
X-1-1 的行数应与需要支模的构件数相当，尺寸来源写 `构件几何`。

**红旗 · 降水与外运要挂工期**：X-1-3 的量 = 降水强度 × 工期，工期来自施工组织，
不来自平面图。土方外运还要看弃土场距离（运距是否单列）与能否场内利用调拨，
这两句业主口径可能完全不同 → 登记时把口径原文一并抄下，
别只留一个孤零零的方量。

## 7. 漏项红旗速查表（交付前逐条过）

| # | 红旗 | 通常意味着 |
|---|---|---|
| 1 | 一段明细里**只有主体没有附属** | 涵洞无端墙、照明无基础、电缆无接地 → 整组漏 |
| 2 | **灯具数正好等于杆数** | 符号—实物 N:1 未识别（1 座高杆 = 6 套灯具） |
| 3 | **同一实物出现两行** | 汇总行 + 明细行并存；墩身 + 墩墙各算一遍 |
| 4 | **同一构件的所有结构层面积相同** | 一个层宽套所有层 |
| 5 | **汇总表与明细表总量不同** | 两处各自维护；或统一参数反算导致 |
| 6 | **分段之和 ≠ 合计** | 扣减项没按段归位 |
| 7 | **读数找不到图面位置** | 该数来自记忆/上一版，非本次取证 |
| 8 | **批量插删行后的相邻区段** | 标题行被吃掉，细目成孤儿 |
| 9 | 交叉复核**两侧完全一致** | 共模错误指纹，不是好消息 |
| 10 | 某量**正好是 1**而你没写过 1 | 兜底默认值 |
