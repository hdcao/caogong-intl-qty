# 房建读图实战（v4.2.0）

> 来源：Port City 港城公寓全量算量实测（1227 个 DWG/DXF → 262 张唯一图 → 224 行台账）。
> 本篇只写**房建与机电房建接口**的实战判定，不复述通用读图流程（见 `drawing-reading-playbook.md`）。

---

## 1. 房建识图的四个"先"

1. **先判体系，再判图种**：项目是几栋、几塔、几种户型、有无裙房/连廊/地下室。
   体系没判清，任何数量都可能是"乘错了"（本项目最大不确定性就是双塔乘数）。
2. **先判平面范围，再判构件**：一层平面、典型层平面、标准层平面、屋面平面，范围不同。
3. **先总量后分解**：先在总体图/表格上读总量（门窗表、面积表、数量表），
   再用平面点算回证。**表格优先于点数（限计数），但口径必须先对齐**——见 §4。
4. **先结构后精装、先主体后附属**：主体结构图定几何，精装/景观图只补做法与植物。

## 2. 图元类型辨识：哪些能数，哪些不能数

房建图纸上同一层里混着四类东西，数错一类就虚报：

| 图元 | 长什么样 | 能不能计安装量 |
|---|---|---|
| **实体构件** | 闭合几何（门扇、幕墙板、柱、洁具轮廓） | ✅ 能 |
| **块实例（构件本体）** | `DOOR`、`GCU`、`PCHL` 之类块 | ✅ 能（按型号分行） |
| **标签块** | `DOOR TAG`、`WINDOW TAG`、`ID-TAG` | ❌ 不能（是标签） |
| **注释文字/标注块** | `ANNO-TEXT-TAG-200`、`ANNO-ROOM.NO` | ❌ 不能（是说明） |
| **图案填充** | `A-WALL-PATT`、墙面填充 | ⚠️ 只能用于识别构件类型，不能当数量 |
| **示意符号页** | `X-UNIT-*` 图例页、系统样例 | ❌ 不能（只读型号对应） |

**实测校准**：一个项目里 `A-FLOR-ANNO-TEXT-TAG-200` 图层的 `DOOR TAG` 块计数为 19369，
而门本体块只有 1879 —— 差 10 倍。**标签块计数只能用于型号回证，不能用于数量。**

### 数块之前必做的三问

1. 这个块是构件还是标签？看它有没有几何轮廓、有没有属性定义。
2. 这个图层是布置层还是注释层？看图层名语义 + 该图层图元的空间分布。
3. 这个数是不是"全楼一次性布置"还是"分层重复"？
   （桩位平面、雨水立管编号都是全楼一次性布置，不乘层数；
   幕墙、门窗是分层重复，×层数 ×塔数。）

## 3. 房建图层语义地图（常见族）

> 名称随项目变，**族结构稳定**。遇到陌生项目先建一张"图层语义表"，写进台账 note。

| 族 | 含义 | 计量注意 |
|---|---|---|
| `A-FLOR-*` | 建筑平面 | 主体 |
| `A-DOOR` / `A-GLAZ` / `A-CURW` | 门 / 玻璃 / 幕墙 | 分型号，与门窗表回证 |
| `A-WALL-PATT` | 墙体填充 | 只判类型 |
| `A-ANNO-TEXT-TAG-200` | 文字标注 | **不是构件** |
| `A-FLOR-ANNO-DIMS-*` | 尺寸标注 | 长度量纲来源 |
| `A-FLOR-ANNO-ROOM.NO` | 房间名 | 房间数口径（不等于套数） |
| `A-FLOR-LEVL` | 标高与楼层名 | 楼层数与层高的唯一权威来源 |
| `X-UNIT-*` | 符号图例 | **不计安装量** |
| `HC-L-SWS-FITTINGS` | 给排水附件（洁具） | 按洁具型号分行 |
| `HC-MECH-*` / `HC-FP-*` | 暖通 / 消防 | 消防符号量易被 top10 截断少计 |
| `HC-FD-*` | 电气 | 灯种须从图例读型号 |
| `HC-Balcony Risers` | 阳台立管 | 按编号去重（并集），不按圆计数 |

## 4. 计数优先，口径先行

**标题改过一次**（v4.6.1）。原文叫"表格优先原则"，容易被读成"照抄表格就对了"——
而表格错得最安静的一类，恰恰是**数量完全正确、口径完全不对**。

房建最可靠的**计数**来源是图纸里的表格，不是点算：

- 门窗表（型号 / 数量 / 尺寸）→ 门窗总量主源；
- 面积表（分区面积、套内面积）→ 面积量纲主源；
- 数量表（桩位、洁具表、灯位表）→ 计数主源；
- 房间名标注 → 房间数主源（不等于户数）；
- 户型统计表 → 户数与户型构成主源（但常常是业主口径，需交叉验证）。

点算的定位是**回证**：用平面点算去核对表格总量，差异必须解释，
不能"两个数选一个"。

**但"数量相符"不等于"可以直接用"。** 表的统计口径是设计院的口径，不是合同计量口径。
至少四组必然出错的口径差：

| 表 | 表里的口径 | 合同常要的口径 | 典型偏差 |
|---|---|---|---|
| 门窗表 | 洞口尺寸（`BAIE`），按"樘" | 铝合金/塑钢按**框外围面积**，玻璃按**见光面积**，卷帘按洞口面积 | 每边 2~5 cm，幕墙面积差 3~8% |
| 面积表 | 建筑面积（当地规范口径，阳台半计/不计，法国 SHON/SDP） | 楼地面**净面积** / 模板**接触面积** / 可售面积 | 同栋楼三个数能差 10~20% |
| 桩表 | 设计桩数 | 施工桩数（含试桩、锚桩、检测补桩） | +2~5%，试桩常单列 |
| 户型统计表 | 业主/销售口径的户数与套内面积 | 计量口径户数（含储藏/物业/架空层） | 户数差几十户（本项目 653 vs 658） |

**这是全流程最难被抓的一类错**：有表格出处、有图号、有页码，门禁查不出（数值自洽）、
复核人回图也看不出（图上就是这个数）——只有到对量/结算被业主一句"你这是洞口面积，
我们计量按框外围"打回，整项重算。房建里门窗 + 幕墙 + 面积三项通常占造价 15~25%。

**所以顺序是：先做口径映射，再用表计数。** 逐列写明「洞口/框外围/见光」「建筑面积/净面积/可售」
「设计桩/施工桩」；映射未完成 → 表只能作回证，不得作交付量。

**实测**：桩位图 ST-03 得 192 根、地下室 GA ST-04 得 172 根，差 20 根。
处理方式不是取大取小，而是按专业图优先级（承台专业图为准）+ 记 OI，
同时用桩顶标高标注（TypeA+TypeB1 共 186）暴露第三个不闭合数字。

### 4.1 表 × 图差异三分类（判定表，v4.6.0）

"差异必须解释"这句话太软，落不到动作。**差异只有四类，每类处置固定**：

| 情形 | 含义 | 严重度 | 处置（**不许取大取小**） |
|---|---|---|---|
| **表有 · 图无** | 表列了但图上找不到 | 高 | 逐个回图复核；确实无对应标注 → 挂 RFI（图漏画 / 表过期，二选一必须由设计定） |
| **图有 · 表无** | 图上有但表未收 | 中 | 先查表是否**分节**（`TIMBER / ALUMINUM / GLASS`、`INT/EXT` 分节最常漏一节）；确认后按图计 + 挂 OI |
| **数量不符（图 > 表）** | 可能表漏列，直接影响采购 | 高 | 按型号逐条列差；**差异未解释前该型号不出交付值**（不是"先按图算着"） |
| **数量不符（图 < 表）** | 可能识别遗漏，也可能是设计变更 | 中 | 先用版本比对（`$TDUPDATE` / rev / 哈希）排除变更，再回图复核；排除变更后按"漏数"处理 |

四类的共同前提：**每一条差异都要落到具体型号/编号**，只报"总数差 20"无法处置。

### 4.2 编号体系前置判定（判错则整张表分行逻辑错）

统计门窗/洁具/灯具前，**先判项目用哪套编号**：

| 体系 | 特征 | 统计规则 |
|---|---|---|
| **序号制** | `M1`、`C2`、`F3`——编号只是流水号 | **编号 ≠ 规格**：同一编号在不同位置可以是不同尺寸，每次出现各计 1 樘，规格回图逐个确认 |
| **编码制** | `M1124`（1100×2400）、`C0915` | **编号 = 规格**：同编号同规格，可按编号聚合后再 ×出现次数 |

判据：看表里是否有"编号 → 尺寸"的一对一映射。有 = 编码制；同一编号对应多个尺寸 = 序号制
（此时表本身可能已错，须先挂 OI 再统计）。

**这一条判错，整个统计表的分行逻辑都是错的**——序号制按编号聚合会把不同规格的门合并，
编码制按每次出现计数会重复计量同规格门。

## 5. 数量型资产的四个特别坑

### 5.1 房间数 ≠ 户数
房间名标注数是**逐套标注实测**（本项目 16~23F 卧室标注数与户型构成推出的卧室数完全相等，
所以不乘实例数）；户型块 `UNIT-67` 之类命名不统一，带不带 `-1BR` 后缀混杂，
必须按块名后缀与图面位置双判。

### 5.2 全楼一次性布置 vs 分层重复
- 一次性：桩位平面、雨水立管编号、屋面设备基础 → **不乘层数**；
- 重复：幕墙、门窗、洁具（分层）、楼板 → **乘层数 × 塔数**。

### 5.3 编号并集 ≠ 出现次数
雨水立管图上每个编号在左右两侧各一根 → 按编号去重取并集（22 个编号）再 ×2，
而不是按文字出现次数（会翻倍）。

### 5.4 图层合计不得截断
只统计 top10 图层会漏掉长尾。实测中 `X-UNIT` 图层由 196 修正到 534（少计 63%）。
**图层合计必须全量统计，不许 top-N。**

## 6. 复本与版本：房建专属判定

### 四图号族
同一张楼层平面被拆成 `CD-700_A/B/C/D` 四个图号（同 sig、同批时间戳）。
按文件数计量 → 4 倍虚报。**同 sig 只取 1 张。**

### 版本冲突
同一构件在结构图与建筑图尺寸不同、或两个桩图数量不同，
先比文件内部版本时间（DXF header `$TDUPDATE`，儒略日基准 2415020），
较晚者为准；差异写 OI。**不要用"文件名更新得晚"当版本依据**——本项目两个桩图
只差 3.2 秒，实际是转档时间差异，不是设计变更，这一点必须诚实标注为"暂按"。

## 7. 房建口径词表（扩展）

除通用口径词外，房建常见：

| 口径 | 说明 |
|---|---|
| 全楼一次性布置 | 图纸只画一次，覆盖全楼（桩位、立管） |
| 分层重复 ×N | 逐层重复，需乘层数 |
| 逐套标注实测 | 房间名一类，逐套标注，不乘实例数 |
| 型号分行列账 | 门窗、洁具、灯种按型号分行 |
| 表格主源·点算回证 | 总量取表，平面点算只做回证 |
| 图例读型号 | 从符号页读型号对应，不出安装量 |
| 业主口径 | 业主提供的统计口径（户数/套内面积），须交叉验证 |
| 暂按（待确认） | 按某版暂定，必须挂 OI |
