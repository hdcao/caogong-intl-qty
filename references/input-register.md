# 建册：图纸台账与算量范围声明（第 0 步；**全量/中档强制，轻档免册**，见 SKILL.md 三档表）

**这一章解决的是"我到底在算什么"**——在打开任何一张图之前，先把
"从哪一版图的哪一张、算什么工作包、算什么部位、哪些还没到手"写成**一张可复核的表**。

> **例外**：轻档（核对单个数值）**不建册**，交付物首行写一行范围声明即可，不受下文 `CONFIRMED` 约束。
>
> ★全量 / 中档**强制**：建册状态不是 `CONFIRMED` 时，算量结果只能以
> `DRAFT` 交付，`build_input_register.py` 退出码为 **1**。
> 外面的同类做法是"只报告不阻断、永远 exit 0"——那等于建了一张没人看的表。

---

## 一、为什么必须做（三个真实的坑）

| 坑 | 现象 | 建册怎么防 |
|---|---|---|
| 图号猜错 | 拿着 `HA-035187` 找图，找不到，白费一轮（真号是 `HA-0351187`，少一位） | 台账以**磁盘实有文件 + 图面标题栏**为准，图号对不上就列 open item |
| 版本裁决 | 澄清函/Addendum 下发了新版图，主图包里还是旧版 | `Rev` + `Superseded By` + `asof` 三列，旧版必须写"被谁替代" |
| 范围不清 | 一张图在不在算量范围内没人书面说过，事后各说各话 | `Scope Status`（full/partial/excluded）+ `Work Package` + `Part` 逐张声明 |

还有两个隐性收益：**文件哈希**能在结算争议里证明"我算的是这一版图"；
**待确认清单**让"缺图"变成一条有责任人的记录，而不是口头提一句。

---

## 二、固定格式（不要改列、不要改页签顺序）

`build_input_register.py` 输出 `input_register.xlsx`，四个页签：

| # | 页签 | 内容 |
|---|---|---|
| 1 | `Cover` | 项目元信息、建册状态（`CONFIRMED`/`DRAFT`）、统计、签发栏（留空） |
| 2 | `Drawings` | 图纸台账，一图一行 |
| 3 | `Scope` | 算量范围声明（口径/含/不含/约定） |
| 4 | `Open Items` | 待确认清单（脚本能证明的缺口 + 人工声明的） |

`Drawings` 列（固定 18 列）：

`序号 | 图号 | 图名 | 专业 | 工作包 | 部位/分段 | 版本 | 图纸日期 | 比例 | 源类型 | 文件 | SHA-256 | 算量范围 | 被替代为 | 关联构件 | 确认人 | 状态 | 备注`

受控取值（写别的会被归一到安全值，并记一条 open item）：

| 列 | 允许值 | 缺省 |
|---|---|---|
| `状态` | `confirmed` / `received` / `pending` / `missing` / `superseded` | `pending` |
| `算量范围` | `full` / `partial` / `excluded` | `full` |
| `源类型` | `vector` / `raster` / `pdf` | 按扩展名推断 |

★`工作包` 与 `部位/分段` 两列的语义：
- **工作包**回答"这张图喂给清单的哪一部分"（如 `WP-04 桥梁`、`2.3 BRIDGES`）
- **部位/分段**回答"在哪"（如 `桥1`、`CH6+000~CH8+000`、`IC-102`），全项目通用图写 `全项目`
- 只有图号、没有这两列，**等于没说这张图在算什么**

## 三、怎么用

### 3.1 从磁盘扫描起册（推荐起点）

```bash
python scripts/build_input_register.py scan --dir <图纸目录> \
        --project "SPARK EPR-1" --out takeoff/register/
# -> drawings_seed.csv（图号/文件名/页数/SHA-256 已填，其余待补）
```

扫描只做机械活：从文件名认图号、算哈希、标源类型。**图名、工作包、部位必须人填**
——脚本不猜（这也是它不自动 `confirmed` 的原因）。

### 3.2 补齐后正式建册

```bash
python scripts/build_input_register.py build --register takeoff/register/drawings_seed.csv \
        --project "SPARK EPR-1" --out takeoff/register/ --rev-addendum "Addendum-2（2026-10-15）"
```

产出 `input_register.xlsx` + `input_register.json`。

### 3.3 判定与退出码（★强制点）

| 建册状态 | 条件 | 退出码 | 后果 |
|---|---|---|---|
| `CONFIRMED` | 无 `open`/`pending` 待确认项，且每条 `confirmed` 都有确认人 | **0** | 可进入算量 |
| `DRAFT` | 存在 open/pending 项 | **1** | **算量成果只能标 DRAFT，不得作为交付** |
| 无台账 | 台账空/文件不存在 | **2** | 门禁未执行 |

`--allow-draft` 可以把 1 降级为警告，但会在 `Cover` 页盖 `DRAFT` 章，并在
`Open Items` 里记一条"以 DRAFT 强行推进"。**降级必须写进交付说明**——这是
"事后各说各话"的唯一解药。

### 3.4 脚本能自动证明的 open item

不靠人填，脚本自己会算出来的：

1. 声明有图、磁盘上找不到 `文件`
2. `状态=missing` 但 `关联构件` 为空 → 缺了这张图影响哪些构件，没人说得清
3. `状态=superseded` 但 `被替代为` 指向的图号不在台账里
4. 图号重复且版本不同，且没有互相标注 `被替代为`
5. `状态=confirmed` 但没有 `确认人`
6. 一张图 `算量范围=full` 但 `工作包` 为空 → 不知道喂给哪一条清单
7. 文件哈希缺失（脚本会补算；找不到文件时无法补）

## 四、与后续步骤的衔接

- 台账里的 `部位/分段` 是后面三维模型与算量表的 **zone/part 字段来源**；
  两边不一致时以台账为准（台账是 Stage 0，先于一切）。
- `图号` 就是算量表「出处」列允许出现的最小单位。算量行写出处时，图号必须
  在台账里存在且状态不是 `missing`——这是出处可信的下限。
- 台账的 `版本` 与 `图纸日期` 喂给 `gate_basis_freshness.py` 的 `drawing_set_rev`
  与每条基准的 `asof`。**新版图下发 = 建册要改版 = 相关基准全部重看**。

### 4.1 多簿合并：sheet 白名单必须人工定（2026-10-24 增补）

一份委托里出现**两个以上工作簿**时（土建簿 / 安装簿 / 分包返簿），
建册阶段就要把 sheet 白名单写死：

| 字段 | 要求 |
|---|---|
| 簿名 | 精确文件名，**不用简称**（`VIADUC_…xlsx`，不写"桥表"） |
| 页签名 | 该簿里进汇总的页签，逐个人工勾选 |
| 用途 | 该页签喂哪张汇总（成本取量 / 支座明细 / 敞口台账） |

**为什么**：外部实测教训——两个分包簿都有「1_成本取量总表」，
按 sheet 名取表**取错簿**，数值差 100 倍而流程全绿（`failure-modes.md` F-E16）。
sheet 名不是身份，**（簿名, 页签名）才是**。

**机器侧的对应动作**：所有取页签的地方（门禁 / 审阅稿 / 汇总脚本）
一律显式传 `--sheet` 且不设默认值；`make_review_html.py` 已把 `--sheet`
设为必传，页眉写明双身份。白名单本身写进交付说明，随交付物走。

## 五、一句话

**建册不是文档工作，是范围锁定。** 一张表把"算哪一版、算哪部分、哪里还没到位"
锁死，后面所有门禁才有共同的坐标系。
