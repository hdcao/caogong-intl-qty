# 失败模式总目录（算量踩坑库）

**什么时候读**
- 建模/取量**之前**读 §三 B 组（几何）与 §四 C 组（口径）——大部分错在这里出生
- 落表/交付**之前**读 §六 E 组（落表与导出）
- 出现一个新错：先在 §一 归因到八根因，再决定归到哪一组、补哪条门禁
- 交付前扫一遍 §九 危险信号（20 条，全是"看起来没事但其实有事"的指纹）
- 汇报"已覆盖某风险"之前：查本表的「现状」列，**没写门禁编号的就是没覆盖**

> 元规则：**一个静默默认，就是一个等着被签字的错数。**
> 本表只收"算术检查抓不到"的失误——算术错 Excel 自己会报，这里的每一条都曾产出
> 一个"看起来很合理"的数量。

**扩充说明（1.3.0）**
- 根因由六条扩到 **八条**：新增 **R7 只建模主体不建模它的尾巴**、**R8 同类构件当成同一个构件**。
- 归入来源两批：① `quantity-takeoff v2` 的 P39–P52；② 2026-10-21 阿尔及利亚 ANESRIF 铁路桥
  （VIADUC PK295+300，APS 阶段三方裁决）的 14 条实测教训，台账见 §十。
- **没有新增分组**：A–E 五组是按"错在哪个阶段"划分的，两批新条目都能定位到阶段，
  强行新开一组反而增加查找成本。归属理由写在每组表下方。

## 一、八条根因（比记 90 个现象更重要）

| # | 根因 | 典型表现 | 通用防护 | 本项目实例 |
|---|---|---|---|---|
| **R1** | **静默默认** | 缺值当 1 / 当 0 / 当上一段；`x or default` | 缺值一律 fail-closed；确需默认的，默认值必须写进假设台账并出现在交付物 | 梁数不给就当 24 片；`geometry.count` 缺失兜底成 1 |
| **R2** | **区间无覆盖证明** | 分段表缺一段，兜底到最后一段；小计区间漏几行 | 断言 `Σ段 = 总长`；每个小计区间必须等于本组有效行范围 | 排水表 9 个分组小计错了 8 个（G-SUB 抓） |
| **R3** | **一个实物多个计量入口** | 汇总行 + 明细行、双编码、墩身与墩墙各算一遍 | 每个实物只有一个 owner 行；其余置 0 并写"不计量，原因=…" | 墩身 360 + 墩墙 420（真值 210）（G-OWN3 报 WARN） |
| **R4** | **参数挂错层级** | 一个宽度套所有结构层；一层厚度套所有分区 | 宽度/厚度/层数绑定到**层/构造/分区**，不绑到构件或项目 | 路面四层同宽；桥宽 26.0m 当横向 |
| **R5** | **单源采信** | 图注与图面矛盾时挑一个；只说"按图" | 两源不一致 → `conflict` + 提澄清，不许二选一 | 箱涵台账 vs Addendum-2 表 5 处差异（CL 挂账） |
| **R6** | **生成物被当成文档** | 手改 xlsx、写完不回读、基准不随表更新 | 只改生成器；写入后回读断言行数/列数/关键格；基准带时效锚 | G8 基线未随落表更新 → 门禁全绿但读的是旧值 |
| **R7** | **只建模主体，不建模它的尾巴** | 涵洞只算洞身、照明只算灯杆、电缆不算接地导体、主梁不算横隔梁 | 每个主体过一遍 `appurtenance-pairing.md` 三张表（附属 / 陪随 / 系统树）；"图纸未见"不许直接置 0，要挂图号待核 | 横隔梁、支座垫石整项漏；台区前墙未计价 |
| **R8** | **同类构件当成同一个构件** | 桥2 套桥1 的梁断面、所有箱涵用一个壁厚 | 结构体系与断面**逐座判定**，参数必须带自己的图号；"和某某一样"必须有图证 | 梁断面跨桥外推；箱涵壁厚 450/400 与 400/350 被统一 t=0.30 |

**归因练习**：遇到新错先问"它属于哪一条"。归不了因的：
- 多半是"没定 owner"——那属于 R3 的变体；
- 若是"整项根本没进清单"——那属于 R7，不是 R2（R2 是区间漏，R7 是构件漏）；
- 若是"两边都有出处却互相矛盾"——那属于 R5 的变体：**不是二选一，而是压根没比**。

### 双证法：关键参数必须有两条独立证据（2026-10-21 定型）

同一张图上读出来的数，**再读一遍还是同一个错**。凡是要进算式的参数，都要有两条互相独立的证据：

| 参数 | 第一证（图面） | 第二证（另一源） | 实测代价 |
|---|---|---|---|
| 梁断面 / 梁高 | 梁断面详图尺寸 | 尺寸链闭合 + 业主清单 U 数反算 | 7841.66 → 3403.50 CM（−57%） |
| 梁片数 | DEMI COUPE 等距块 | 支座表 / 业主清单梁条数 | 支座 234 → 260 |
| 台身厚 | 台区剖面尺寸链 | 逐张图核对（3/3 一致）+ 体积量级对比 | 69.66 → 503.10 CM（+622%） |
| 盖梁宽 | 盖梁自身宽链各段之和 | 与桥宽对比（**不等是常态**，相等才要查） | 1052.64 → 971.04 CM |
| 支座个数 | 支座表直读 | 梁端数 × 每端支座数（推导式，不是硬编码） | 差 26 个 |
| 高程 | 高程链自下而上闭合 | 纵断面表 / 实测 FSR | 差一个承台厚 |

**两证不合的解法不是取中值**，是回图找出第三证或挂澄清。

## 四、C 组 · 口径与编码

5. **F-C16 / F-C17 横隔梁、支座垫石整项漏**（垫石钢筋按配筋率推，差 3.4 倍）——R7 整组无机器防线
6. **F-C10 名称数量词与量列不符**（24 片 / 36 榀）——建议 G-NAME
7. **F-B14 桩长未按 NOTE 校核**——本项目敞口，涉 480+2,532 LM
8. **F-C11 线性量未扣结构物长度**——建议断言 `计量长度 == 路线长 − Σ结构物长`
9. **F-B09 / F-B10 构造层数与逐层扣减**——靠人读大样
10. **F-D05 外部成果版本演进**——只比最新版
11. **F-B19 / F-B20 跨构件外推与逐座差异被统一**——建议断面参数强制带自己的图号（可作 G-C 的扩展字段）
12. **F-A06 文字被转矢量轮廓 / F-A09 文本层解析漏抓**——读图工具层
13. **F-E13 层级标题被批量插删行吃掉**——建议 G-HIER（孤儿明细 + 段头唯一性）

**加门禁的顺序**：先看它是否曾造成真实金额损失，再看判据能不能做成数值型。
两条都不满足的，写进交付说明让人盯，比加一条只会喊"注意"的门禁有用。
**F-C20 排在首位是因为它最贵**：它不是"没查"，是"查了三遍都没查到点上"——单列防线再密，
列与列之间的缝还是要靠**跨列比对**堵。

## 九、危险信号（看到就停下来查）

- 某个量正好是 **1**，而你从没写过 1 → R1，有人在 `or 1`。
- 两个不同编码的值**完全相等** → F-C01（分层共用面属正常，同对象同部位才可疑）。
- 分段量之和 ≈ 总量 × 1.5 / × 2 → F-C02。
- 同一构件的所有结构层**面积相同** → R4（各层宽度被套成了同一个数）。
- `inputs` 里出现你没填过的键 → 有人在兜底。
- 复核脚本通过率 100%，但关键参数没人回图核对 → F-D01。
- 交付目录出现 `_new`、`~$`、`(1)` 后缀 → F-E07。
- 同一份交付物里，汇总表和明细表给出**不同的总量** → F-D09。
- 一段明细里**只有主体没有附属**（涵洞无端墙、照明无基础、电缆无接地、主梁无横隔梁）→ F-C12/C14/C16。
- 灯具/喷头/风口数**正好等于**杆数/支管数/设备数 → F-C15。
- 高程/深度类参数你没填过却出现在 `inputs` 里 → F-B05（有人在按经验兜底）。
- **修正后某一项变化超过 ±50%**（本项目三次：−57%、+622%、−8%）→ 原值不是"误差"而是**错参数**，
  必须写进修正台账并回查同族构件有没有同样的错。
- **同一行的单位列与口径声明各说各话** → F-C20。
- **门禁全绿，但你刚刚重建过工作簿** → F-E09（先看 `verified_at` 与表 mtime 的先后）。
- **某个构件在所有图上"都找不到"，但业主清单里有** → F-C16/C17（多半是漏项，不是业主多列）。
- 抽取/解析出来的回路数、构件数与图上目测**差一点点** → F-A09（分词或行序问题，不是数量问题）。
- 汇总写"全部门禁通过"，但你不知道每道门禁**检了几行** → F-D12（分母为 0 的通过不是通过）。
- 两侧数值"完全一致"，而它们共享**同一套列映射或同一份中间产物** → F-D11 / F-D02（一致是共模的指纹，不是正确的证据）。
- 一个名称子串同时命中**父项与子项**（"承台"命中"承台垫层"）→ F-D13。
- 跨簿合并时按 sheet 名取表，而**两个簿有同名 sheet** → F-E16（身份必须是「簿名 + sheet 名」）。

## 十一、怎么往里加一条

1. **先归因**：这条新错属于 R1~R8 哪一条？归不了就先问是不是 R3（没定 owner）、R7（整项没进清单）。
2. **写现象用可检索的句子**：写"把纵向梁区总长当桥面宽"，不写"读图有误"——半年后你要搜得到。
3. **防护写动作**，不写原则："逐层累加，每层单列"，不写"要仔细"。
4. **现状列必须诚实**：有门禁写编号，没有写「未覆盖」。**写"已注意"是最坏的写法**——它既不是防线，也堵住了后来人补防线的路。
5. 若这条能做成数值判据，去 `gate-library.md` 加判据，并**先造一个它该抓的错做注入验证**。
6. **带上数字**：来自真实项目的，把"原值 → 真值、差百分之几"写进现象列，并追加一行到 §十 台账。
   没有数字的条目，半年后你不会记得它为什么重要。
